# 魔王ワーク（仮） — Phase 1 プロトタイプ

> **最上位の設計指針:** [GAME_DESIGN_PRINCIPLES.md](GAME_DESIGN_PRINCIPLES.md)
>
> 個別仕様・UI・数値・コンテンツ量よりこの文書を優先し、最重要KPIを「もう1回遊びたいか」とする。
> 開発を引き継ぐ場合は [`HANDOFF.md`](HANDOFF.md) も読むこと。

お前は魔王だ。自分では戦わない。**面接して、採用して、組み合わせから壊れた魔王軍を作れ。**

ブラウザだけで動く魔王軍運営ローグライト。応募してきたモンスターを採用し、最大20体の軍団を作る。
毎回3つの作戦から進路を選び、王国を8拠点攻略すれば勝利。強さの源は個々のステータスではなく、
**モンスター同士の組み合わせ（シナジー）**にある。

## 再設計後の到達目標と現行仕様

本作の最上位体験は、履歴書を見て「こいつを今の軍団へ入れたら何が起きる？」と考え、
発火・連鎖・再発火から、そのラン固有の壊れビルドを作ることである。

現在の出撃隊／控え、給与、忠誠、食料、建材、施設、事件は、この体験へ移行するための土台として残す。
後方を独立した管理ゲームへ拡張しない。食料は消費・飢餓・暴食のトリガー、施設はランの規則を
変える大型シナジー装置、戦闘は構築結果を可視化する舞台へ段階的に再構成する。

現行のPhase 1セットシナジーは人数条件と倍率が中心だが、汎用CHAINとOVERKILL基盤、代表3ビルドの
実連鎖は実装済み。大型施設は恐喝帳簿・巨大厨房・墓地から1つを選択できる。装備は未実装である。
以下の遊び方と数値は「現在遊べる仕様」であり、到達目標との差分と移行順は
`docs/SYNERGY_CONNECTION_AUDIT.md` を正本とする。

## 遊び方

### 2026-09-05：略奪の連鎖と戦闘演出

《強欲》は味方が金貨を得たとき、各人・同じ連鎖で1回、威力70%で追撃する。
盗む者と反応する者を別々に採用でき、追撃者が新しい金貨を出せば別の仲間にも続く。
戦場の上に起点と発火理由を表示し、戦果には起点の名前を残す。
連鎖の起点・初条件・決着は読み、中間反応は畳み掛ける（強弱）。ただし各段に下限
（攻撃0.56秒・OVERKILL0.8秒・その他0.52秒）を置き、一瞬では流さない。イベントは省略しない。
説明は次の出来事まで残り、「ここまでの連鎖」で読み返せる。履歴を開くと一時停止する。
「読むために停止」と既存の2倍・4倍も利用できる。勝利は0.9秒の間→約3.2秒のファンファーレ→次へ。
試写は `battle-preview.html#loot`。固定編成を本物の戦闘計算で再生し、本編のセーブは変更しない。

Claudeの食料・シナジー改修も統合済み。軍団全体で人数を数える条件はゴブリン4体、
魔法職4体、アンデッド3体＋死霊術。効果は出撃者だけに適用する。
以下に残る3体・旧倍率の試算例は改修前の記録であり、現行値は能力表示とデータ定義を参照。

`index.html` をブラウザで開くだけ（ビルド不要・サーバー不要・`file://` でも動く）。
GitHub Pages に置けばそのまま公開できる。

最短侵攻なら1ラン およそ10〜15分。寄り道した場合はそのぶん長くなる。
負けると軍団は消滅し、**魔界史**に記録だけが残る。

新規ゲームでは3人の魔王から、その代の経営方針を選ぶ。若き魔王は標準、人事魔王は
所持金を減らして初回採用3名、築城魔王は所持金を建材へ振り替える。恒久強化ではなく、
最初にどの不足を抱えるかを変えるルール選択である。
戦闘は自動で進み、速度（x1 / x2 / x4）と「最後まで飛ばす」を選べる。

## 力くらべ（壁を先に見せる）

作戦カードと編成画面に、**敵の総HP**と**素の殴り合いでの往復**を出す。

- 敵の総HP／敵の1ラウンド火力
- 今の出撃隊の総HP／1ラウンド火力
- 削り切るまで何ラウンド、こちらが倒れるまで何ラウンド
- 判定：押し切れる（緑）／ぎりぎり（黄）／◯ラウンド足りない（赤）

**この見積りに連鎖・シナジー・特性・不祥事は入っていない。** 素の殴り合いの下限であり、
足りない差はプレイヤーが組み合わせで作る。「素では2ラウンド足りない」がそのまま編成の目標になる。

実測（60ラン・477戦）では、判定 clear の戦いは勝率100%、close は89%、
**short は29%** — 素では届かない戦いでも、連鎖とシナジーで3割は覆る。
予測ラウンドと実測ラウンドの差は中央値0。

## 魔王命令（戦いのなかで一度だけ決める）

魔王は戦わない。だが**ラウンド2の終わり**に戦況報告が入り、そこで一度だけ命令を出せる。

| 命令 | 効果 | 代償 |
|---|---|---|
| 📣 檄を飛ばす | 残りの戦闘のあいだ、味方全員の与ダメージ+55% | 出撃者の忠誠 -14 |
| ⚔ 総員突撃 | 全員が最も弱った敵へ**数珠つなぎに**殺到する | 突撃1体につき残業+3時間／突撃した者は被ダメージ+30% |
| 🪙 その場で支払う | 未払いを帳消しにし、味方全員の被ダメージ-30% | 給与総額の半額を即金で |

**命令は1ランで3回まで**。見送りは消費しない。使い切れば戦闘は止まらなくなる。
毎戦使える号令にすると全部の戦いが同じ手順になるので、「ここで使うか、取っておくか」を判断にしている。

総員突撃は連鎖ビルドの引き金である。追加行動が**前の者の一撃を親にして繋がる**ため、
突撃そのものが1本の鎖になり、押し出しがいればそこからさらに伸びる。
固定編成の実測で最大CHAINは 5.2 →（突撃）11.0。ただし5体を走らせれば残業は15時間、
つまり過労と労基署がそのぶん早く来る。

## コアループ

```
応募者3名 → 1名採用 → 作戦会議 → 出撃隊の編成 → 自動戦闘
   ↑                                         ↓
   └── 給与・手当 ← 食料消費・施設建設 ← 勝利資源 ─┘
```

- 軍団は最大20体。その中から作戦ごとに最大5体の出撃隊を選ぶ。**並び順が配置**で、
  先頭ほど狙われやすい（60%）。壁役を前に、魔法使いを後ろに。「最前列へ」で任意の1体を
  一操作で先頭へ移せる。
- 新規ゲームは最初の採用後、そのまま通常の作戦会議へ入る。旧「勇者到着まで3日」の
  開幕専用日程は使わない。
- 6体目以降を抱えると敵が大軍を察知し、1体につき敵能力+2%（最大+6%）の「軍勢警戒」がかかる。
  多彩な控えを持つか、少数精鋭で敵の増援を避けるかも判断になる。
- 作戦は毎回3択。**辺境の略奪**は軍資金と食料、**反乱鎮圧**は忠誠と建材、
  **王国侵攻**は攻略進行と少量の建材を得る。
  寄り道するほど採用候補は育つが、警戒度が上がって以後の敵も強くなる。
- 建設担当と備蓄建材があれば、どの作戦でも勝利後に施設施工が進む。反乱鎮圧は施工専用ではなく、
  建材を最も多く確保しながら忠誠を立て直す作戦である。作戦カードには今回の施工見込も表示する。
- 施設Lv到達時、同時に1つだけ稼働する大型施設を選ぶ。恐喝帳簿は略奪経済、巨大厨房は食事、
  墓地は戦死・召喚を先鋭化する。次のLv到達時には維持または建て替えを選べる。
- 作戦カードには勝利報酬・現在の給与・差引見込を表示する。急いで8回侵攻するか、
  略奪で蓄えてから進むかをプレイヤーが選べる。
- 出撃前に**給与方針**を選ぶ。通常支給は勝利後に全額（控えは半額手当）。
  意図的未払いは0Gでこの戦闘から未払い扱い。
  通常支給でも金庫が足りなければ未払いとなり、連続するほど忠誠低下が大きくなる。
  ただしオークの特性「血の気」は**未払いだと攻撃+60%**になる。搾取は戦術になる。
- 敗北で即ラン終了。魔界史に「第N代／在位年数／最大戦力／主力種族／到達地域／死因」が刻まれる。
  敗北画面では、敵軍を最も追い詰めた瞬間の残HP・削った割合・最後の出来事も見せる。
  「何があと一歩だったか」を見て、再起時に採用・作戦・配置を選び直せる。

## 出撃隊と控え（現行実装）

軍団は**出撃隊（最大5体）と控え**の2層だけ。配属という別操作は持たない。
出撃隊に選ばなかった者が、そのまま控えとして勝利後の調達に回る。

| 層 | 勤務内容 | 給与 |
|---|---|---|
| 出撃隊 | 最大5体が戦場へ出る。生還すれば戦功を得る | 満額 |
| 控え | 勝利後、種族と前職に応じて**食料と建材の両方**を調達する | 希望給与の半額（端数切り上げ、最低1G） |

調達量は適性の**半分ずつ**。片方に専念していた頃の効率は出ないが、
「食料か建材か」を選ぶ操作を無くしたぶん、1人あたりの総量は旧3部門とほぼ同じに保っている。

> **2026-09-06に三部門を畳んだ理由**
> 戦闘／建設・施設／食料・生活の3部門へ毎戦配属していたが、切除計測
> （`docs/WEIGHT_AUDIT.txt`）で、配属をやめると最大CHAIN +0.15・発火種類 +0.7 と
> どちらもノイズ床を超えて改善した。**戦力を戦場の外へ吸い出していた**ということ。
> 編成画面のパネル3枚と毎戦2回の判断を取りながら、連鎖を薄くしていた。
> 「誰を外して将来へ回すか」という判断は、出撃隊の選定そのものに畳んである。

軍団の食料需要は、種族ごとの食う量3につき食料1。出撃隊ぶんは戦闘前に糧食として前払いし、
残りだけを勝利後に消費するため、従来の総需要は増えない。アンデッドは食事不要で、オーガはよく食べる。
戦闘糧食を含む食料不足は、不足量に応じて全員の忠誠を下げる。
一方、食事が足りれば忠誠が少し回復する。建材を投入すると施設が育ち、大型施設が働ける回数が増える。

| 給与方針 | 支払い | 戦術上の意味 |
|---|---|---|
| 通常支給 | 勝利後に通常額 | 忠誠+2。以前の未払いを解消するが、戦闘中はまだ未払い状態 |
| 今回は未払い | 0G | 出撃時から未払い。血の気が乗る一方、ストライキと段階的な忠誠低下が起きる |

宰相モルモは、作戦決定・戦闘後・事件・再起などの節目で**全画面の報告シーン**として現れる。
台詞は短い発話音とともに一文字ずつ表示され、タップ／Enterで全文表示、もう一度で次へ進める。
「次へ」ボタンは押せるようになると**光る**（位置は動かさない。指を置く先が動くボタンは押しにくい）。
読み終われば自動でも次画面へ移る。表情と報告内容は食料不足・施設完成・勝敗に応じて変わる。
正式画像は `assets/mormo/` に置き、制作元の `img/` はゲームから直接参照しない。
現在の正式画像は女の子版6表情。制作原画は `assets/mormo/female/`、旧男の子版は
`assets/mormo/male/` に保存し、ゲームは従来どおり `assets/mormo/{expression}.webp` を読む。

## 戦功と昇進

生還した出撃隊は戦功を1獲得し、撃破・与ダメージ最多・盾役で追加戦功を得る。
戦功16で**将軍**へ昇進し、その場で能力・忠誠・給与が変化する（階級はこの1段だけ）。
将軍まで育つとシナジー「将軍の号令」が発動し、出撃隊全員の与ダメージが15%上がる。
誰を連戦させて育て、誰を控えで守るかが軍団編成の判断になる。輩出した将軍は魔界史にも残る。

## 戦闘中の不祥事

忠誠が低い部下は戦闘中に死んだふりをし、さらに下がると仲間へ襲いかかることがある。
給与未払いの部下は戦場ストライキを起こす。将軍が生存している部隊では発生率が65%減るため、
  昇進は火力だけでなく統率にもつながる。不祥事は戦闘演出・結果画面・魔界史へ記録される。

作戦会議から面接・軍団確認へ、出撃隊編成から作戦会議へ戻れる。相手が弱そうなら高給の主力を控えに置き、
安い部下だけを出して蓄財することもできる。控えを抱える代償は軍勢警戒と軍団全体に起きる事件である。

人材能力とシナジーの成立条件・効果はゲーム内で公開する。編成画面の「組み合わせ候補」から未発動条件も
確認できる。隠すのは、複数能力を実際に組み合わせたときの連鎖結果と壊れ方だけである。

これらは連鎖基盤を検証するための入口として維持するが、人数条件＋倍率だけを完成形にはしない。
今後は略奪、金貨、食料消費、戦死、蘇生、召喚、OVERKILLなど、別能力が反応できるイベントを生成する形へ発展させる。
未発見効果をすべて公開することは避けつつ、履歴書と編成画面には仮説を立てられる接続ヒントを出す。

最初の実連鎖として、ゴブリンは既存の《卑怯者》に加えて《追い剥ぎ》を持つ。戦闘で初めて敵へ
ダメージを与えると1Gを予約し、勝利時だけ所持金へ確定する。追加特性《強欲》を持つ個体は、
その金貨獲得へ反応して威力70%の追加攻撃を行う。同じ連鎖では1回だけ発火する。
戦闘中は `攻撃 → 追い剥ぎ+1G → 強欲 → 追加攻撃` が同じCHAINとして表示・集計される。
CHAIN 3以上のダメージには共通の連鎖倍率が乗る。CHAIN 3で×1.25、CHAIN 4で×1.75、
以後1段ごとに+0.25（最大×2.50）。強欲だけでなく、暴食の宴やOVERKILL伝播にも適用する。
そのため連鎖は記録を伸ばすだけでなく、発生中のダメージそのものを大きくする。
ゴブリン3体以上なら撃破ごとに《略奪者の連携》でさらに1Gを予約する。施設Lv.1以上で会計職を出撃させると
試験施設《恐喝帳簿》が有効になり、予約金貨が初めて3Gへ達した瞬間、次の味方攻撃を40%強化する。

食料にも最初の実連鎖がある。《大食漢》は食べられれば与ダメージ+25%、《魔界料理人》は
消費量に応じて最も大食いの味方を強化する。4以上消費すると《暴食の宴》でラウンド1後に追加行動し、
支払いによって備蓄が0へ変化した瞬間は《飢餓の悪魔》が全軍与ダメージ×2・被ダメージ+30%を発火する。
編成画面は消費予測と発火見込みを表示し、戦闘では食料消費から各能力までを同じCHAINで示す。

死亡・蘇生にも最初の実連鎖がある。死霊術師は《墓守》として、味方が初めて死亡したとき魂を回収する。
《死霊術》で味方がアンデッドとして蘇生すると、《魂の徴収》持ちが魂1を消費し、生存中のアンデッドを
与ダメージ+20%（最大5回）ずつ強化する。戦闘では `死亡 → 魂獲得 → 蘇生 → 魂消費 → 強化 → 再攻撃`
を同じ因果CHAINとして表示する。蘇生できず戦闘終了時に倒れている人材は、従来どおり永久戦死する。

連鎖そのものを狙って作る能力群もある。段数（`chainDepth`）を読むのは次の4つで、
どれか1つでは何も起きない。伸ばす役・火力へ変える役・資源へ変える役がそろって初めて壊れる。

| 特性 | 役割 | 効果 |
|---|---|---|
| 押し出し（コボルト／インプ） | 伸ばす | 鎖の中で仲間が敵を倒すと、その鎖でまだ動いていない自分が威力60%で追撃。1鎖1人1回 |
| 深追い（オーク／オーガ） | 火力へ | 連鎖3段目以降、1段深まるごとにダメージ+60% |
| 深淵の恐怖（ゾンビ） | 火力へ | 連鎖1段につき敵防御を15%無視（最大75%） |
| 歩合（ゴブリン） | 資源へ | 連鎖が3段目に達するたび、深さぶんの金貨を略奪予約。1鎖1回 |

押し出しを何人採ったかが鎖の長さの上限になる。歩合が出した金貨には既存の《強欲》が反応するので、
`撃破 → 押し出し → 撃破 → 歩合+2G → 強欲 → 追加攻撃 → …` と別系統へ乗り換えて伸びる。
連鎖は `Battle.MAX_CHAIN_DEPTH`（12段）で頭打ちにする。

**代償は戦闘の外にある。** 4段目以降の味方の行動は「残業1時間」として数え、勝利後に請求する。
2時間につき出撃者の忠誠-1（最大-20）、3時間につき備蓄食料-1（夜食）。
連鎖ビルドは1戦を壊せるが、壊し続けると忠誠が落ちてストライキ・退職事件が起き、
食料も先に尽きる。**一度の爆発は無料でも、連発は買えない。**
残業は個人にも積み上がり（出撃した者だけ）、戦果画面の「今回の大暴れ」に最大CHAINと並べて出る。
自慢と請求書を同じ場所に置いている。

### 残業が盤外へ漏れ出す先

積み上がった残業は、戦闘と戦闘の間のハプニングとして帰ってくる。

- **労基署の抜き打ち**（軍団の累計12時間〜）：罰金（累計の半額・上限24G）を払って是正するか、
  **会計職に帳簿を書き換えさせる**（罰金ゼロ、ただし次回の罰金が倍）か、
  **監督官を8Gで引き抜いて労務顧問にする**か、権威で追い返す（全員の忠誠-10）。
  労務顧問がいると残業の忠誠低下が半分になるが、残業した戦いごとに顧問料3Gが要る。
  払えなければ顧問は帰り、次の残業から全額こちらへ来る。
- **働きすぎた者**（個人の残業15時間〜）：いちばん働かされた者が倒れる。
  手厚く弔う（5G・全員の忠誠+14）／労災として処理する（保険金6G・全員の忠誠-12）／
  叩き起こして休ませる（軍団に残るが、控えへ回って次の1戦は出撃できない）。
- **残業自慢**（個人6時間〜）：表彰するか、残業削減を宣言する（全員の記録-6時間）か、黙らせるか。

同じ隊を回して連鎖を伸ばすほど個人の残業が集中し、過労が早く来る。
出撃隊を分散させれば過労は避けられるが、押し出しの人数が減って鎖が短くなる。
**連鎖の深さと、それを出せる隊の持続可能性がトレードオフになっている。**

施設Lv.1以上で死霊術師を控えに置くと、試験施設《墓地》が有効になる。最初に死亡した味方を
起点として、ラウンド終了時に骸骨従者を1体召喚する。従者は元の最大HP30%・攻撃50%・固定速度で、
次ラウンドから行動する。給与・忠誠・戦功・永久戦死・出撃上限の対象外で、戦闘終了時に消滅する。
召喚は `死亡 → 墓地発火 → 召喚 → 魂の徴収 → アンデッド強化` と既存CHAINへ接続する。

全滅した瞬間は通常のラウンド終了処理を流さず、《執念》と《墓地》だけを敗北確定前の救済フックとして
一度解決する。1体でも戻れば次ラウンドから戦闘を続行し、戻らなければ従来どおり敗北する。
《死霊術》と《追い剥ぎ》または《強欲》を同時編成すると《殉職手当》が成立し、蘇生した人材が初めて
敵を撃破したとき2Gを予約する。本人が戦闘終了時に再び死亡していれば `resource_forfeit` で没収される。

## 戦闘演出とイベント契約

戦闘は「計算」と「見せ方」を完全に分離している。
`Battle.simulate()` は戦闘を即時に計算し、**イベントタイムライン**を返す。
レンダラ（`src/ui/battle_scene.js`）はそれを再生するだけで、戦闘ルールを一切知らない。

```
Battle.simulate()  →  timeline[]  →  BattleScene.play(timeline)
（ルール・バランス）    （契約）        （DOM/CSS・差し替え可能）
```

この分離により、後から Canvas / WebGL / ネイティブのレンダラに**戦闘シーンだけ**差し替えられる。
バランス調整で数値を変えても演出は壊れないし、演出を作り替えてもバランスは動かない。

### イベント一覧

全イベントは戦闘内で一意な `eventId` を持つ。攻撃・追撃・死亡・蘇生など因果関係を持つイベントは、
`parentEventId`、`chainId`、`chainDepth` も持つ。通常攻撃が深度1の起点になり、そこから生じた死亡や
火球、蘇生は同じCHAINを引き継ぐ。戦闘結果の `chainSummary` はタイムラインだけから導出し、
戦闘計算と別の連鎖状態を持たない。

全イベント共通で `{ type, emphasis, text?, cls? }` を持つ。
`emphasis` は **0=通常 / 1=小 / 2=大 / 3=決定的**。「どれくらい重要か」は戦闘側が決め、
**「何秒見せるか」は描画側が決める**（責務の分割）。

| type | 主なフィールド | 意味 |
|---|---|---|
| `battle_start` | `player[]`, `enemy[]` | 開幕。各ユニットの `{id,name,race,icon,side,hp,maxHp}` |
| `synergy` | `name`, `desc` | シナジー発動（カットイン） |
| `round_start` | `round` | ラウンド開始 |
| `attack` | `fromId`,`toId`,`dmg`,`hp`,`maxHp`,`dead`,`traits[]` | 通常攻撃 |
| `splash` | 同上 + `label` | 火球などの追撃 |
| `survive` | `unitId`,`hp` | 白骨などで致死を耐えた |
| `death` | `unitId` | 撃破 |
| `overkill` | `fromId`,`toId`,`excess`,`percent`,`rank` | 致死時の余剰ダメージとランク |
| `revive` | `unitId`,`hp` | 蘇生 |
| `summon` | `unit`,`sourceUnitId` | 戦闘途中に戦闘専用ユニットを追加 |
| `heal` | `unitId`,`amount`,`hp` | 回復 |
| `resource_gain` | `sourceId`,`resource`,`amount`,`label` | 戦闘後に確定する資源予約 |
| `resource_forfeit` | 同上 | 条件喪失による資源予約の没収 |
| `note` | （テキストのみ） | 特性発動などのログ行 |
| `result` | `victory` | 決着 |

致死時は、実ダメージから攻撃直前の残HPを引いた値を余剰ダメージとする。
**余剰が敵最大HPの40%に満たない撃破はOVERKILLと呼ばない**（`Battle.OVERKILL_MIN_PERCENT`）。
以前は「少しでも余ればOVERKILL」だったため1戦あたり3.94回発生し、余剰割合の中央値は18%だった。
毎回起きるものは見せ場ではなく日常なので、「やりすぎた撃破」だけに名前を与える（実測0.88回/戦）。
敵最大HPに対する余剰割合が
100%以上で《蹂躙》、300%以上で《粉砕》、500%以上で《消滅》、1000%以上で《魔王級殲滅》。
上位ランクは現状のAIプレイでは届かない（実測の最大は約320%）。これは**壊れたビルドで初めて届く目標**
として残しており、ランクの側を下げて簡単に到達させることはしない。
オーガの追加特性候補《連鎖虐殺》は、100%以上OVERKILLした余剰の30%を次の敵へ最大3体まで伝播する。
戦闘演出ではランクごとの光を出し、**《蹂躙》以上（余剰100%以上）だけ画面を揺らしてカットインを出す**。
OVERKILLは1戦あたり約0.88回。そのうち《蹂躙》以上は約8戦に1回で、そこだけが見せ場になる。
戦果画面では「今回の大暴れ」パネルへまとめる。

`revive` と `heal` は**特性の実行前後の状態差分から自動生成**される。
つまり新しい特性を `traits.js` に足しても、描画側を触る必要はない。

### 尺のテーブル（描画側の責任・`battle_scene.js`）

| emphasis | 尺 | 演出 |
|---|---|---|
| 0 | 460ms | 踏み込み＋小さく揺れる |
| 1 | 620ms | ＋攻撃者と対象の表示 |
| 2 | 820ms | 大きく揺れる・数字が大きい |
| 3 | 1050ms | ＋画面全体が揺れる |

特殊: `synergy` 1650ms（専用色のカットイン）/ `round_start` 1150ms / `result` 1200ms。
各ラウンドの間には「前ラウンド終了 → ROUND n」を大きく表示する。攻撃中は攻撃者と対象を
カードの枠と中央字幕で示すため、ログを読まなくても誰が何をしたか追える。
敵ユニットに `introQuote` があれば、開戦時に本人の台詞として中央字幕と戦闘ログへ出す（現在は勇者アレン）。
最終決戦・将軍の号令・不祥事・蘇生・耐久にはそれぞれ色と光り方の違う専用演出がある。

尺は**事件の大きさに比例**する。総尺が予算45秒（x1）を超えたら、
**通常攻撃と何も反応しなかった区間だけ**を縮める（最小0.45倍）。
CHAIN・OVERKILL・シナジー初発見・逆転・蘇生・召喚・永久戦死は縮めず、
むしろ大きさに応じて長く見せる。45秒は上限ではなく予算なので、
事件が詰まった戦闘は予算を超えて長くなってよい。短い戦闘は一切圧縮されない。

| 延長する条件 | 倍率 |
|---|---|
| CHAIN が深い（深度3以上） | +10%×(深度−2)（最大 +50%） |
| OVERKILL | +25%×ランク（蹂躙・粉砕 +50%、消滅・魔王級 +75%） |
| シナジーをそのランで初めて見た | +45% |
| 逆転勝利（総HP3割以下から勝った） | +65% |
| 永久戦死（蘇生せず退場した味方） | +50% |

事件そのものの基礎尺は「読み切れること」を基準に置く。実プレイで能力発火や略奪が
見逃されたため、能力発火1150ms・資源獲得900ms・OVERKILL1250msへ引き上げた（2026-09-02）。
**x1は観戦側に振り、急ぎたい人は速度x2/x4と「最後まで飛ばす」を使う**という分担にしている。

実測の平均演出尺は **序盤13〜16秒 / 中盤24〜30秒 / 終盤35〜43秒**（x1、極端な乱戦は約51秒）。
このうち「縮めない事件」が占める割合は段階を通じて **40〜53%**（`tools/analysis-duration.js`）。
選択は LocalStorage に保存される。

### 効果音

`src/ui/sound.js` が短い90年代RPG風の効果音を管理する。
攻撃と防御は、モーダル成分・ノイズ残差・低域・初期反射を重ねて事前生成した
`assets/sfx/` のオリジナルWAVを使う。「ばすん・がちゃん・ずし・ずばっ」の4系統×3変種。
それ以外はWeb Audio APIで合成し、モルモの発話音を含む合計21種類のキューがある。戦闘速度に合わせて尺も短くなる。
12個のWAVは合計約455KBで、外部素材とライセンスには依存しない。

ブラウザの自動再生制限に従い、最初のクリックまでは AudioContext を作らない。
右下の音声コントロールで音量変更・ミュートができ、設定は LocalStorage に保存される。
生成コードは `tools/generate-sfx.js`、比較試聴は `tools/sfx-lab.html`、設計根拠は
`docs/SFX_RESEARCH.md`。将来録音素材へ交換するときも、呼び出し側は変えず
`Sound.cue()` の中だけを差し替える。
### BGM — 軍団が演奏している

`src/ui/music.js` は通常進行で「魔王軍の行進曲」(**Raiders March**) を流し、
戦闘開始時には独立した **Battle RPG Theme** へ曲頭から切り替える（ともにCC0）。
どちらの曲にも**プレイヤーが組んだ編成が薄い楽器レイヤーとして加わる**ため、
場面の躍動感を変えながら「自分の軍団が鳴っている」手触りは維持される。

| 鳴るもの | 鳴る条件 |
|---|---|
| 足音（バスドラム） | 常時。テンポは王国警戒度で上がる |
| 行進ベース | 出撃隊の頭数。5体なら分厚く、1体ならスカスカ |
| 号令ラッパ | 将軍がいる |
| 不気味なコーラス | アンデッド（骸骨兵・ゾンビ・死霊術師）の数 |
| 魔法の鈴 | 術者（インプ・魔法使い・死霊術師）の数 |
| 間の抜けた裏拍 | スライム系がいる |

さらに **軍団の不満が演奏を壊す**。給料未払いの隊員はアクセントをサボり、
平均忠誠が低いと音が抜けて拍がよれ、実曲の厚みも少し痩せる。
給料を払わないと行進曲がだれていくのが耳で分かる。

構造は戦闘と同じで、計算と見せ方を分けてある。

```
Music.describe(state) → descriptor → Music.apply(descriptor)
（軍団の解釈・純関数）   （契約）      （CC0実曲＋同期アクセント）
```

通常曲は約62秒、戦闘曲は約114秒のループ。スマホで埋もれないよう音量を整え、
Ogg Vorbisへ最適化してある。配布元とCC0の記録は `assets/bgm/LICENSES.md`、
設計の根拠は `docs/BGM_DESIGN.md`。
BGMだけを切りたいときは、画面下の音声コントロールに触れると出る `♪` ボタンを押す
（常時表示にすると固定パネルが広がり、下の「解雇」ボタンへ近づくため隠してある）。

### 絵を発注するときの仕様

**現状は絵が1枚も無くても動く**（絵文字とCSSだけで演出が成立している）。

### 立ち絵の追加手順

1. `assets/monsters/{id}.png` を置く（`id` は `monsters.js` の `id` と同じ）
2. `src/data/portraits.js` の配列に `id` を足す

これだけで採用画面と戦闘画面の両方に反映される。
一覧に載っていない種族は絵文字のまま。載せたのにファイルが無い場合も、
一度だけ読み込みを試して自動的に絵文字へ落ちるので壊れない。

一覧方式にしているのは、未収録の種族に対して毎回404リクエストが飛ぶのを避けるため。

### 画像の仕様

| 項目 | 指定 |
|---|---|
| サイズ | **768×1024（3:4／履歴書の証明写真の比率）** |
| 容量 | 1枚80KB以下 |
| 顔の位置 | **上から55%以内**に収める |
| 構図 | バストアップ、正面〜やや斜め、カメラ目線 |
| 背景 | 証明写真らしい無地（透過でなくてよい） |

「顔は上55%以内」が重要なのは、同じ画像を**戦闘画面では34px角に切り抜いて**使うため
（`object-fit: cover; object-position: top`）。顔が中央より下にあると首から下だけが表示される。

もう一つの制約は**小さくても判別できること**。採用画面では54×72、戦闘画面では34px角まで
縮むので、シルエットと1つの識別的特徴（角・色・被り物など）だけで種族が分かる必要がある。

履歴書写真だけでも、踏み込み・被弾・撃破・復活の**動きはCSS側が持っている**ため成立する。
追加の戦闘立ち画は任意で、`BattleScene.BATTLE_SPRITES` に登録した種族だけ
`assets/battle/units/{id}/idle.webp` を待機立ち、`attack-windup.webp` を攻撃キーポーズとして使う。
未登録・読込失敗時は従来の履歴書写真または絵文字へ落ちる。

戦闘立ち画は512×768の透過WebP、汎用エフェクトは512×512の透過WebPを基本とする。
汎用エフェクトは `assets/battle/effects/` の `slash`、`impact`、`guard`、`revive`、`overkill`。
生成原本をゲーム用へ整える処理は `scripts/prepare_battle_units.py` と
`scripts/prepare_battle_effects.py` に置く。静止画をCSSで拡大・回転・フェードさせるため、
AIへ不安定な多フレームスプライトシートを生成させない。

**画風の統一が最大の難所**なので、1枚ずつ個別に生成せず、必ず同一プロンプト・同一設定で
シリーズとして生成すること。

## 再起（1ランに1度だけの巻き戻し）

全滅しても、**1ランに1回だけ「再起」できる**。

- 戻り先は「戦闘の直前」ではなく**直前の採用フェーズの開始時点**（＝一戦手前）
- コストは**所持金の半減**。魔界史にも「再起1回」が刻まれる
- 使い切って敗北するか「ここで終わる」を選んだ時点で確定し、魔界史に記録される

戻り先を戦闘直前にしていないのは意図的である。この戦闘は自動かつ乱数を含む
（ダメージ0.9〜1.1倍、狙い先60%、怪力20%）ため、同じ戦闘をそのまま再挑戦できると
**単なるサイコロの振り直し**になり、採用・編成の判断がすべて無意味になる。
採用フェーズまで戻すことで、やり直せるのはサイコロではなく「編成の判断」になる。

実装は `Game.saveCheckpoint()` が採用フェーズ開始時に状態をディープコピーするだけで、
戦闘ロジックには一切触れていない。

### セーブのライフサイクル

| 状態 | セーブ | 「続きから」 |
|---|---|---|
| ラン進行中 | 残る | 途中の画面から再開 |
| 敗北・再起可能 | **残る** | 再起の選択画面から再開 |
| 敗北確定／全クリア | 消える | 出ない |

再起可能な敗北状態もセーブされるため、負けた直後にブラウザを閉じても再起の権利は失われない。

## 戦死は本当の退場（欠員募集）

戦闘で倒れたモンスターは**軍から永久に去る**。給与計算より前に外れるので、
**死者に給料は出ない**。

- 次の面接では「通常1名＋欠員数」まで補充できる（3体死ねば3回分の面接が回る）
- 結果画面に戦没者パネルが出て、魔界史にも戦没者数と名簿が残る

これが無いと、死亡が戦闘内でしか意味を持たず**次の戦闘で全員が全快で復帰する**ため、
最期の台詞も戦死バッジも意味を失っていた。同時に、採用フェーズが
「欠員が出たから募集する」という本来の意味を持つようになった。

### 蘇生した者は退場しない

判定に `died`（一度でも倒れたか）ではなく **`survived`（最終的に生きていたか）** を使う。
これにより **死霊術・執念・白骨といった蘇生系の特性が「永久退場を防ぐ保険」に化ける**。
戦果パネルでも 💀戦死 と ✨生還 を区別して表示する。

### バランスへの影響

勝利した戦闘の43%は無傷。ステージ別の平均戦死数は第1〜2戦がほぼ0、
第7戦2.3体、第8戦2.9体（`node tools/analysis-casualty.js` で再現可能）。
序盤は無傷なので死のスパイラルにはならず、終盤だけ消耗が激しい設計になっている。

導入によるクリア率（各150ラン）:
魔法職寄せ 47% / スライム統一 45% / 中盤で精鋭に転換 41% / ゴブリン統一 24% /
最強優先 23% / 骸骨寄せ 17% / 安月給 13%

少人数編成ほど戦死が少なく欠員補充が効くため、「中盤で精鋭に転換」が
24%→41%と大きく伸びた。編成方針の選択に新しい意味が加わっている。

### ツケ（後で祟る選択の伝票）

「得だが後で祟る」は、その場で効かせてしまうと成立しない（ただの割の悪い取引になる）。
そこで **種別と数値だけを持つ伝票** を `st.debts` へ積み、戦闘が終わるたびに期限を1つ縮め、
満期のものを支払う。関数を持たないのでセーブ・ロードを跨いでも壊れない。

- **勝敗を問わず取り立てる。** 負ければ踏み倒せるなら、ツケは判断ではなく抜け道になる
- **プレイヤーに隠さない。** 編成画面と戦果画面の「🧾 ツケ」に、あと何戦で何が来るかを出す。
  理由の分からない不幸は事件ではなく理不尽になる
- 祟りの種別は `Game.DEBT_KINDS`（金貨・食料・建材・警戒度・施設Lv・忠誠・最大HP・
  未払い・労働争議・出奔）。**新しい祟りはエンジン側に1ケース足す**（イベント側に関数を書かない）

検証は `node tools/test-debts.js`。

登場人物は参照ではなく **uid** で保存しているので、途中でセーブして再開しても壊れない。
給与抗議を無視した場合だけ `laborDispute` が残り、後日の事件抽選でストライキ行進へ続く。
検証は `node tools/test-labor-events.js`。

## 給与未払いの罰則

当初は未払いでも一律「忠誠-15」だったが、実測すると **300ラン中1回（0.3%）しか
離脱が起きておらず**、脅しが空砲になっていた（8戦しかないランでは忠誠0に届かない）。

連続で未払いにするほど痛手が増える形（-15 → -30 → -45…）に変え、支払えば
連続回数はリセットされる。結果、離脱の発生率は **0.3% → 5.7%** になった。

なおオークの特性「血の気」は未払い時に攻撃+60%なので、**あえて払わない**という
選択も戦術として残っている。

## 求人の出し直しと、シナジーが「全振り」に報いる設計

### 求人を出し直す

採用画面では応募者3名を入れ替えられる。**同じ面接内で1回目は無料、2回目以降は
広告費が 2G → 4G → 8G と倍々に増える**（採用すると次の面接でリセット）。
無料採用枠を使い切っても面接は自動終了しない。さらに採りたい場合は紹介料を
4G → 8G → 16G と払い、不要ならプレイヤーが「面接を終了して作戦会議へ」を選ぶ。
紹介料は即時費用であり、表示される希望給与は戦後に支払う維持費なので別物である。

これが無いと、目当ての種族が来ない回に「打ち切る＝誰も採らない」しか選べず、
頭数で負けて狙った編成を組む戦略だけが一方的に不利になっていた。
かといって無制限に無料で引き直せると緊張感が消えるため、費用を上げていく形にした。

### シナジーは頭数に応じて伸びる

当初シナジーは「3体以上で+30%」という固定値だったが、実測すると
**シナジーを完成させた純粋な軍団が、シナジー無しの混成軍に大敗していた**。

| 第7戦の勝率（各400回） | 修正前 | 修正後 |
|---|---|---|
| 混成の強豪（シナジーなし） | 92% | 94% |
| ゴブリン×5（ゴブリン軍団） | 46% | 80% |

原因は3体で頭打ちだったこと。4体目・5体目が何も足さないので、
弱いティア1個体で5枠を埋めるコストに見合わなかった。
頭数に応じて倍率が伸びる形に変え、「全振り」が報われるようにしている。

現在の第8戦（最終決戦）の勝率は 魔法結社×5 が 73%、死の軍勢が 28%、
ゴブリン×5 が 6%、混成が 4%。狙って組んだ編成ほど強い、という関係になった。

## 履歴書としての採用画面

応募者には数値だけでなく **前職・志望動機・短所** がある。

```
前職      前魔王軍・第三破壊部隊
志望動機  金払いがいいと聞いた
短所      細かい作業ができない
```

笑いの源は「就活という真面目な様式 × 被写体のダメさ」のギャップなので、
文体は履歴書のまま崩さずに書く。種族ごとに口調と価値観を変えており
（ゴブリンは卑屈で金にがめつい、骸骨兵は慇懃で古風、スライムはひらがな、など）、
`src/data/monsters.js` の `prevJobs` / `motives` / `flaws` に追記するだけで増やせる。

履歴書欄は**採用画面のカードにだけ**表示する。編成画面は元々スクロールが長いため、
そこには出さない（`monsterCard(m, { resume: true })`）。

応募者が持つ能力と現在の軍団が直接つながる場合、履歴書には最大3本の発火経路を表示する。
たとえば既存人材が《追い剥ぎ》、応募者が《強欲》なら、
`追い剥ぎ → 金貨獲得 → 強欲` と読める。これは同族ボーナスの推薦ではなく、異なる人材の
「何を生む能力」と「何に反応する能力」を結ぶもの。直接接続がなければ、相性を捏造せず
「現在の軍団との直接接続はまだない」と表示する。表示語彙は特性の任意メタデータ
`links.emits / links.reacts` から導出し、戦闘計算や効果量には使わない。

## 戦闘後の一言

戦果パネルの各行には、その戦闘で何が起きたかに応じた**本人の一言**が付く。

```
🐕 ロボ            👑殊勲 💀戦死
████████████  65与ダメ / 1撃破
「魔王様……申し訳……ありま……」

👺 ヌゴ                   💀戦死
███           20与ダメ
「だから、逃げていいって……言った……」
```

戦闘が始まると全員が数値に還元されてしまい、採用画面で作った人格が消える——
という問題への対策。状況の判定は既に計算済みの戦果データから行い、優先度は

**戦死 ＞ 給与未払い ＞ 殊勲 ＞ 何もできず ＞ 被弾最多 ＞ 勝敗**

の順。台詞は `src/data/monsters.js` の `voices`（`dead` / `unpaid` / `mvp` /
`idle` / `hurt` / `win` / `lose`）に種族ごとの口調で書く。追記するだけで増える。

画面の再描画で台詞が変わってしまわないよう、選択は戦闘直後に一度だけ行い
`lastBattle` に保存している（`Game.attachVoices()`）。

## キングスライム合体は断れる

スライム3体で出撃すると、既定では従来どおり1体のキングスライムへ合体する（不可逆）。
ただし編成画面で**断れる**。硬く重い1体を取るか、頭数で伸びるもの
（低賃金大量採用・群れの本能・出撃枠の圧）を保つかの判断になる。

編成画面には「3体のまま」と「合体して1体」のHP・攻撃・給与を並べて出す。
既定を「合体しない」にして測ったらスライム統一のクリア率が48%→29%へ落ちたので、
**既定は合体のまま**にしてある（黙って弱くしない）。

なお merge型のシナジーは「実際に合体した戦闘」でだけカットインと戦果へ載る。
条件を満たしているだけで「合体する！」と宣言してしまう不具合は、この実装で直した。

## 傭兵市場（稼いだ金貨の出口）

出撃前に金貨を払って、**その戦闘だけの6体目**を雇える。出撃5枠は壊さない
（設計憲法 第3節「6体目以降は高コストな特殊解禁として扱う」）。

- 候補2名から選んで雇用。1人目 10G、2人目 20G、1戦闘に最大2人
- **顔なじみ価格**：出撃隊に同じ種族がいるほど安く来る（1体につき10%、最大40%引き）。
  能力で選ぶか、安さと種族シナジーの頭数で選ぶかが判断になる
- 候補は作戦ごとに固定（編成をいじるたびに引き直せると「今いる候補で決める」判断が消える）
- 傭兵は**軍団員ではない**。給与も戦功も昇進も無く、倒れても欠員・戦没者名簿に入らない。
  戦闘が終われば去る（戦果パネルには 🗡傭兵 として出る）
- 城の施設補正（HP・防御）は自軍と同じく効く

**同族を雇えば種族シナジーの頭数も増える**ので、「硬い者を雇うか、噛み合う者を雇うか」が判断になる。
実測ではゴブリン5体編成の第7戦勝率が、オーガ傭兵で61%、ゴブリン傭兵で91%（傭兵なしは8%）。

これは略奪経済ビルドの出口として入れた。ゴブリンは1ランで14.9Gを略奪するのに、
その金が終盤の戦闘に対して何もせず、**ビルドを完成させたランのクリア率が12%で最低**だった
（第5戦時点のゴブリン数別・400ラン実測）。金貨→頭数→種族シナジー→さらに略奪、で環を閉じる。

## 編成画面のシナジー予告

シナジーの効果量は「+15%刻み」のような説明文ではなく、**いまの編成に実際に適用して測った値**を出す。

```
✨ ゴブリン軍団
   いま：与ダメージ ×1.15（対象 3体）
   ▲ オーガをゴブリンに替えると 与ダメージ ×1.30
```

- 出撃枠が空いていれば「同じ種族をあと1体で ×1.30」、埋まっていれば「誰を誰に替えれば伸びるか」
- 未発動でも、手持ちを増やして届くものは「あと○体」を出す
- 効果量・入れ替え候補・不足人数はすべて `Synergy.preview()` がシミュレーションで導出する。
  データ側に説明用の数値を二重に持たせない（効果を変えたとき表示だけ古くなるため）
- シナジーだけでは「混ぜると倍率を二重に失う」の片方しか見えないので、
  **編成で決まる特性**（《群れの本能》＝同族1体につき+10%、《忠犬》など）も
  `Synergy.traitEffects()` が実際に `modDealt` を呼んで測り、「いまの並びで効いている特性」として出す。
  敵の状態やラウンドで変わるもの（《卑怯者》《先制》《怪力》）は中立な状況を渡すことで自然に外れる

これは「人材本人の能力・発火条件・効果は公開する。隠すのは組み合わせの結果と壊れ方だけ」という
設計契約の実装でもある。実測では **ゴブリン3体＋オーガ2体（第6戦の勝率28%）より
純ゴブリン5体（100%）のほうが強い**——耐久を足したつもりで倍率を失っていた——のに、
画面には「+15%刻み」としか出ておらず、その差が見えていなかった。

## 戦果パネル（貢献度の可視化）

戦闘後の結果画面（勝利・敗北とも）に、部隊の誰がどれだけ働いたかを**棒の長さで一発表示**するパネルがある。
数字を読み比べなくても、バーの長さだけで「今回は誰が主力だったか」「誰が何もできなかったか」が分かる。

- 1行は「アイコン＋名前＋与ダメージ」「バッジ」「バー」の3段。
  名前とバッジを同じ行で取り合わせない（働いた者ほど名前が消えるため）
- 与ダメージの多い順に並ぶ（バーの長さ＝最大貢献者に対する比率）
- 👑殊勲：最も与ダメージが多かった1体
- 🛡盾役：最も被ダメージを受けた1体（殊勲と別の場合のみ表示）
- 💀戦死：その戦闘で倒れた場合

集計は新しい状態を戦闘中に持ち回るのではなく、**確定済みのイベントタイムラインから毎回導出する**
（`Battle.summarizeContribution()`）。ログや演出と同じ「タイムラインが唯一の真実」という設計を踏襲している。

### 火力以外の働き（非ダメージ貢献）

与ダメージだけでは「略奪した」「仲間を戻した」「能力を何度も撃った」が消えてしまうので、
個人行にはその戦闘で確実に本人へ帰属できる働きだけをバッジで出す。0の項目は出さず、最大3つまで。

| バッジ | 中身 | 由来イベント |
|---|---|---|
| 💰+3G | 金貨の純増減（略奪 − 没収） | `resource_gain` / `resource_forfeit` の `sourceId` |
| ✨1蘇生 | 他者を戻した回数＋自己蘇生（《執念》） | `revive` の `sourceId`、無ければ `unitId` |
| ⚙4発火 | 能力を発火させた回数 | `trait_trigger` の `sourceId` |
| 魂+1 | 魂の純増減 | 同上 |
| 💚+6 | 回復した量 | `heal` の `unitId` |

施設由来の発火や召喚された骸骨従者は「誰の手柄か」を言えないので、無理に個人へ付けない。
**非ダメージ貢献は表示だけで、戦功・昇進の計算には一切入らない**（評価の軸を増やすと、
「強い編成」がぼやける）。

### 今回の大暴れ（主要記録は2つだけ）

勝利・敗北・ゲームオーバーの各画面へ、同じ「💥 今回の大暴れ」パネルを出す。

CHAIN は**ひとつの出来事が次の出来事を引き起こした段数**である。
`攻撃 → 追い剥ぎ +1G → 強欲 → 追加攻撃` なら4段で、最大CHAINは4。
用語を説明する画面は作らず、記録の下に経路そのものを出して意味を読ませる
（「いちばん長くつながった連鎖（4段）」の一行を添える）。

- **最大CHAIN** と **最大OVERKILL** の2つだけを見出し記録にする
- その下に**代表CHAIN経路**を一本だけ並べる（例: `攻撃 → 追い剥ぎ +1G → 強欲 → 追加攻撃`）
- OVERKILLの回数・総余剰、蘇生回数、召喚数は下の詳細1行へ回す

経路は最深イベントから `parentEventId` を逆にたどって導出する（`Battle.deepestChainPath()`）。
分岐した枝や全CHAIN一覧は出さない。記録を横並びに増やすほど、どれも読まれなくなるため。
因果メタデータを持たない古いセーブでは経路だけが消え、パネルは壊れない。

### 施設と死者の働き（2倍速でも手柄が読める）

「今回の大暴れ」の下に「🪦 施設と死者の働き」パネルを出す。実プレイの2倍速で
「同じゾンビが二度立ち上がった」ように見えたとき、それが執念か、死霊術か、
死の軍勢の全快か、墓地による別個体の召喚かを、戦闘を見返さずに区別するためのもの。

- **共通補正**（施設Lv.のHP・防御）と**稼働中の大型施設**（Joker）を別の行に書く。
  どちらを体感したかを分けて読めるようにし、共通補正を撤去するかの判断材料にする
- 稼働施設が発火した場合は何をしたかを1行で書く（例: `墓地：骸骨従者1体を召喚（全滅回避）`、
  `恐喝帳簿：予約金貨3G到達 → 次の味方攻撃+40%`）。発火しなければ「今回は発火しなかった」
- **死者の連鎖**は倒れた味方ごとに1行。`致死を耐えた → 戦死 → 死霊術で蘇生（全快） → 骸骨従者を召喚`
  のように並べ、戦闘終了時に戻っていなければ末尾に「永久戦死」を付ける

集計は `Battle.summarizeFacility()` と `Battle.summarizeDeathChains()` がタイムラインだけから導出する。
「全滅回避」は召喚の時点で開始時の味方が全員倒れていたかを再生して判定する。
どちらも表示専用で、戦功・昇進・報酬には接続しない。要約を持たない古い戦果ではパネルごと出ない。

## 敵にも特性がある

ボス格の敵ユニットは味方と同じ `TRAITS` フックを使い、専用の見せ場を持つ。

| 敵 | 登場 | 特性 |
|---|---|---|
| 将軍グラハム／団長ヴァレス | S6/S7ボス | 怪力（20%でダメージ2倍） |
| **勇者アレン** | S8 最終ボス | **覚醒**：自身のHPが50%以下になると、以後ダメージ+50%（1戦闘1回） |

「覚醒」は最終戦の約8割で発動する（実測）。追い詰めたはずの勇者が終盤に急に強くなる、
という一発逆転の緊張感を狙った設計。序盤〜中盤の敵には特性を持たせていない

### 敵編成の揺らぎ

第1〜第7攻略段階には「基本隊列」と、人数・前衛耐久・速度配分が違う代替隊列がある。
総合戦力は基本編成の概ね±10%だが、多人数横隊には範囲攻撃、少数精鋭には単体火力など、
同じ採用方針でも相性が変わる。編成名と特徴は作戦カード・編成画面で事前に開示する。
編成画面から戻っても同じ作戦会議中は敵を引き直せない。最終戦の勇者アレン一行は固定。

検証は `node tools/test-enemy-formations.js` と `node tools/sim.js 50`。
（S4/S5に特性を足すとクリア率が半減以上したため、味付けは最終盤に絞った）。

### なぜフレームワークを使わないか

Phase 1 の規模（全体で約1,500行）ではReact等の利点が費用を上回らない。素のJSなら
ビルド工程ゼロで GitHub Pages に置け、`file://` の直接オープンでも動き、`fetch` を使わないので
CORS 問題も起きない。状態は `Game.state` 一つで、画面は毎回作り直す方式のため、差分描画の仕組みも要らない。
UIが複雑化して差分更新が必要になった段階で再検討する。

## 拡張のしかた

**モンスターを増やす** — `src/data/monsters.js` にテンプレを1つ追記するだけ。名前・台詞・職業のプールから
個体が自動生成される。

**特性を増やす** — `src/data/traits.js` にフックを書く。使えるフックは5種類：

| フック | 呼ばれるタイミング |
|---|---|
| `modDealt(ctx)` | 与ダメージ計算時（`ctx.mult` に乗算する＝倍率は掛け算で重なる） |
| `modTaken(ctx)` | 被ダメージ計算時（新しいダメージ値を返す） |
| `postAttack(ctx)` | 攻撃直後（追加攻撃・デバフ） |
| `onRoundEnd(ctx)` | ラウンド終了時（再生・蘇生。死亡中にも呼ばれる） |
| `onLethal(ctx)` | 致死ダメージの瞬間（`true` を返すとHP1で耐える） |

**シナジーを増やす** — `src/data/synergies.js` に `check(units)` と `apply(units)` を書く。
`apply` は `u.mods.dmgMult` などを**乗算**で書き換える。加算ではなく乗算にしているため、
複数のシナジーが噛み合うと数字が指数的に伸びる。

**バランスを確かめる** — `node tools/sim.js 400` で、7種類の採用戦略それぞれ400ランを回し、
クリア率・敗北ステージ・シナジー出現数を表示する。データを追加したら必ず流す。

現在の想定クリア率（各200ラン・再起1回を使う前提）:
スライム統一 57% ／ 最強優先 46% ／ ゴブリン統一 40% ／ 魔法職寄せ 35% ／ 中盤で精鋭に転換 23% ／ 骸骨寄せ 23% ／ 安月給 11%

## 保存

LocalStorage のみ（ゲーム進行は3キー、ほかに音量・速度などのUI設定キー）。

- `maou_save` — ラン途中の状態。各操作ごとに自動保存され、タイトルの「続きから」で復元。敗北時に破棄。
- `maou_history` — 魔界史。ランをまたいで永続。各代の生存者から戦功優先で1名を殿堂入りとして保存する。

- `maou_kpi` — KPI測定（下記）。ラン状態とは別に持ち、**外部へは一切送らない**。

### 各代の主要記録は最大CHAINと最大OVERKILLの2つだけ

勝敗と到達点のほかに、その代がどれだけ壊れたビルドを作れたかを示す記録として
**最大CHAIN**と**最大OVERKILL**の2つだけを魔界史へ残す（設計憲法 第11節）。

- ラン状態の `maxChain` / `maxOverkill` を各戦闘の終了時に更新する（勝敗を問わない）。
  値は `chainSummary.maxChain` と `overkillSummary.maxPercent` との最大値
- **再起で一戦手前へ戻ると、この2つもチェックポイント時点へ戻る**。やり直した歴史の記録は残さない
  （巻き戻しても残る別記録は作らない）
- クリア・敗北のどちらでも `endRun()` が歴史レコードへ保存する
- 終了画面の「第N代魔王軍の記録」と魔界史の各カードで、`⛓ 最大CHAIN` と `💥 最大OVERKILL` を近接表示する
- 総余剰ダメージ・獲得G・召喚数・代表CHAIN経路などは主要記録へ並べない。
  数字を並べるほど「数字だけのゲーム」に寄るため
- フィールドの無い古いセーブ・古い魔界史は0として安全に扱う

殿堂入り人材は次代以降、1ランにつき25%の抽選に通ると最初の面接へ再応募する。
同じ名前・種族・履歴書を引き継ぐが、能力値・戦功・階級は新任として生成し直す。
歴史がゲームへ戻る仕掛けであり、周回を有利にする恒久強化ではない。
魔界史画面には魔物採用図鑑もあり、一度でも採用した種族だけが開示される。
途中で戦死・離反しても採用記録は残り、未採用種族の名前と能力は伏せる。
同じ画面のシナジー図鑑は、実戦で発動させたシナジーだけ名前と効果を開示する。
魔王実績は魔界史から後計算し、征服だけでなく未払い、施設、殿堂入り、図鑑完成も周回目標にする。
解除による能力ボーナスやポイント通貨はない。

## KPI測定（端末内で完結・外部送信なし）

最重要KPI「もう1回遊びたいか」を感想ではなく行動で測る（設計憲法 第14節）。
`src/core/kpi.js` が記録し、`maou_kpi` へ保存する。**ゲーム内に分析画面は作らない。**
先に画面を作ると数字を眺めて終わるため、記録の契約だけを持つ。

| 記録 | 中身 | 何を切り分けるか |
|---|---|---|
| `buildAttempts` | 前戦から人材・特性・施設・**傭兵・合体の可否**・狙う資源状態（作戦・給与方針）のいずれかが変わった戦闘数 | 1ランで仮説を何回試せたか。同じ編成の連戦は数えない |
| `formationChanges` | 出撃隊の選抜・並び替えを変えた回数 | 組み替えに手が動いているか |
| `mercenariesHired` / `kinHires` / `mercenaryGold` | 雇った傭兵の数・うち同族・払った金貨 | 金貨の出口が使われているか。同族が多ければ「ビルドを濃くする買い物」 |
| `mergesRefused` | キングスライム合体を断った回数 | 既定を覆す判断が起きているか |
| `quickRetry` | 前のランの終了から60秒以内に次のランを始めたか | リトライ率＝「もう1回」の実測 |
| `sessionRun` | そのセッション（ページを開いている間）で何本目のランか | セッション内ラン数 |
| `speedChanges` / `logSkips` | 戦闘速度の変更・戦闘スキップの回数 | 尺が長いと感じた合図 |
| `reportSkips` | モルモ報告を**全文表示前に**送った回数 | 報告が読まれているか |
| `lastScreen` | 最後にいた画面と攻略段階・作戦数・日数 | どこで手が止まったか（途中離脱） |

読むときは DevTools のコンソールで `copy(KPI.export())` し、保存したJSONを
`node tools/kpi-report.js kpi.json` へ渡す。「ビルド試行 ÷ 戦闘数」が高ければ
**既存の材料は試し切られている＝足りないのは種族・役割**、低ければ
**足りないのは試せる回数・組み替えやすさ**、と切り分けられる。

再起（チェックポイント巻き戻し）でKPIは減らない。魔界史の最大CHAIN・最大OVERKILLとは
逆の扱いで、これは意図的である（やり直した編成も「試した回数」ではあるため）。
`node tools/sim.js` も同じ計測を通るので、AIプレイのビルド試行回数を基準線として見られる。

## Phase 1 で意図的に作っていないもの

新モンスター・新特性・新施設の解禁／装備／
複数魔王／敵側の特性／画像素材／サウンド／イベント・ストーリー。

（戦闘演出は Phase 1 の後に追加済み。画像素材はまだ使っておらず、絵文字とCSSのみで成立している）

恒久成長は「魔界史が積み上がる」ことだけに限定している。**攻撃力+1%のような恒久強化は入れない**——
長期プレイで増やすべきは強さではなく、選択肢・組み合わせ・発見・歴史だと考えているため。
殿堂入りはこの原則のまま実装済み。図鑑も魔界史の蓄積を使う方針とする。

## 演出を書くときの規律（スマホ対応のため必ず守る）

将来 Capacitor でスマホアプリ化する前提のため、以下は例外なく守る。

1. **アニメーションは `transform` と `opacity` だけ**を使う。
   `left/top/width/height` を毎フレーム変えるとレイアウトが走り、実機で必ずカクつく。
   HPバーも `width` ではなく `transform: scaleX()`（`transform-origin: left`）で伸縮させている。
2. **ゲームロジックからDOMを読まない。** DOMは書き込み専用の出力先。
   要素の座標を測ってゲーム状態を決める、は禁止。
3. **レンダラはインターフェース越しに呼ぶ**（`BattleScene.play(timeline)`）。
   ここを守る限り、Canvas版やネイティブ版への差し替えは戦闘シーンだけの置換で済む。
4. **`core/` と `data/` にブラウザAPIを持ち込まない。**
   現在この2層はDOM非依存で、`node tools/sim.js` がブラウザ無しで全ゲームロジックを実行できる。
   `storage.js`（31行）だけが LocalStorage に触れており、ネイティブ保存への差し替え口になっている。

`prefers-reduced-motion: reduce` の端末では演出を自動的に抑制する。
