# 仕様：城のメニュー——画面を「今やること」と「いつでも見るもの」に分ける（2026-09-11）

実装担当：CodeX（Terra）。この文書と `HANDOFF.md` §0・§2 だけで始められる。
迷ったら末尾「未決」を見て、無ければ**いちばん小さく、いちばん今の見た目に近い**ほうを選び、コミットメッセージに書く。
背景（オーナー 2026-09-11）：「見にくい。スマホだと縦にスクロールする。採用のとき既存メンバーのステータスが見られないのは痛い。
メニューで分けて表示させよう。隊列ではざっくり、タップで詳細。ステータスメニューは重複だから無しでいい」。

## 0. 一文で

**画面は二層にする。「今やること」（面接→作戦→編成→戦闘→結果）は今までの流れのまま。「いつでも見るもの」は城のメニュー（3つの札）に集め、どの場面からも開けて戻れる。** 人物の詳細は札を**タップして開く**一つの画面に統一し、採用・隊列・記録のどこからでも同じものを見る。

## 1. 構成

### 1.1 城のメニュー（`UI.castle(tab)`）— 札は3つだけ

オーナー案の7項目（採用・城の記録・軍団員ステータス・隊列・シナジー・習得技・進行度・施設）を、**性質で3つに畳む**。札が多いとスマホで並ばない。

| 札 | 中身 | 今どこにあるか |
|---|---|---|
| **軍団** | 名簿を一覧（出撃隊が上、留守番が下）。各行は**ざっくり**（顔・名前・種族/職・階級・HP/攻/防/速・気合・負傷/未払いの印・技の名前1つ）。行の操作：出撃⇄留守番の切替、並び（▲▼⏫）、解雇。行をタップで**人物の詳細**（1.3）。 | `formation()` の中身 + `departmentButtons` |
| **記録** | 日誌／蔵／去った者（今の「城の記録」をそのまま）＋ **進行度**（王国攻略 n/8、魔王軍Lv、警戒と反撃の予告、勇者の状態、城陥落の回数、伝承で覚えた技の一覧）。 | `records()` + HUD の数値 |
| **参謀** | 発動シナジー（見取り図と今の発動状況）／施設（Lv・稼働・次の施設）／作戦会議の敵情（選んだ作戦があれば）。 | `chainMapPanel` `synergyPanel` `facilityPanel` `enemyPreview` |

- 入口：HUD の「📖 城の記録」ボタンを **「🏰 城」** に置き換え、押すと前回開いていた札で開く。札は上部に横並び（スマホでも3つは並ぶ）。
- どの場面（面接・作戦会議・編成・結果・施設選択・事件の前後）からも開けて、「← 戻る」で**元の場面へ**（`st.phase` は変えない。今の `recordsFrom` の仕組みを流用）。戦闘中は開けない。
- **編成の場面では「軍団」札の下に「出撃する」ボタンを固定表示**（1.4）。つまり編成画面は「城のメニューの軍団札＋出撃ボタン」になる。今の `formation()` は薄い殻にして、中身は札と共有する（二か所で別々に組まない）。

### 1.2 採用（面接）は「今やること」のまま。ただし既存メンバーが見える

- 面接画面の応募者の札の下（スマホでは上）に、**今の軍団の一覧をざっくり一行ずつ**（軍団札の行と同じ描画。操作ボタンは無し、タップで詳細）。これで「誰と比べて採るか」が同じ画面で分かる。
- 応募者の札もタップで詳細（採用前でも同じ画面。ボタンは「採用する」）。

### 1.3 人物の詳細（`UI.memberDetail(uid | applicantIndex)`）

一つの画面（スマホでは全面、PC では中央のカード）。**軍団札・面接・記録（去った者は名前だけ）から同じものを開く。**
中身：顔（大）・名前・種族/職・階級と戦功・HP/攻/防/速（基礎値との差＝小成長を小さく）・気合・特性（癖・共通特性・遺物由来を印で分ける）・技（1段目/上位技、上位技なら「お披露目済み／号令でだけ」）・次に覚える技か伝承・記録（出撃数・倒れた・担がれた・遅刻・食べた）・忠誠・給与・一言（quote）・遺物。
操作：出撃⇄留守番、解雇（確認あり）、遺物を渡す/戻す（蔵があるとき）。応募者なら「採用する」。閉じると元の画面へ。
**数値は出してよい**（ステータス画面は数値の見返しの場所。癖の説明文は今までどおり数値を書かない）。

### 1.4 スマホ（幅 560px 以下）

- 各場面の**主ボタンを画面下に固定**（「出撃する」「この作戦を選ぶ」「次へ」）。長い画面でもスクロールせずに押せる。
- HUD は2行に畳む：1行目「所持金・食料・建材」、2行目「魔王軍Lv・王国攻略・警戒（反撃ゲージ）・🏰 城」。残り（作戦数・給与・軍団数・地域）は記録札の進行度へ。
- 編成の「参謀卓」（見取り図・シナジー・敵情）は編成画面から外して参謀札へ。編成画面は軍団の一覧と出撃ボタンだけにする（縦の長さを半分以下に）。
- パネルは `<details>` で畳めるものは畳む（既定：開く）。

- `src/main.js` — action：`castle`（`data-tab`）、`castletab`、`backcastle`、`member`（`data-uid` / `data-index`）、`closemember`。既存の `records` / `backrecords` は `castle` / `backcastle` に寄せる（互換で残してよい）。

`UI.set(html, scene)` は **scene を必ず明示**（"castle" / "member"。見出し文字からの推定に頼らない）。

## 3. 進め方

- 速度優先。軽いモデルのサブエージェントを並列（軍団行・詳細画面・札の枠・CSS・ブラウザテストで分ける）。担当ファイルは重ねない（`ui.js` は関数単位で分ける）。統合とコミットは親。
- コミットは3つに分ける：**A 人物の詳細＋面接の軍団一覧**（いちばん痛い点を先に）／**B 城のメニュー（3札）と編成の組み替え**／**C スマホの固定ボタンと HUD 2行**。A だけでも試遊に出せる形にする。
- 各コミットで `run-all.sh` 全通過。sim・node の再計測は不要（規則は変えない）。

## 4. 受け入れ条件（`tools/browser-tests/castle.js`）

- 面接で応募者と既存メンバーが同じ画面に見え、既存メンバーをタップすると詳細が開いて閉じられる（phase は recruit のまま）。
- 城のメニューが作戦会議・編成・結果から開き、3つの札を切り替えられ、「← 戻る」で元の場面へ（phase 不変）。
- 軍団札で出撃⇄留守番の切替・並び替え・解雇ができ、`Game.state.activeUids` が変わる。編成の場面では「出撃する」が押せる。
- 記録札に日誌・蔵・去った者・進行度がある。参謀札に発動シナジーと施設がある。
- 幅 390px で、編成画面の縦の長さが今より短く（`document.body.scrollHeight` を今の値と比べて記録）、主ボタンが画面内に固定されている。
- JS エラーなし。既存テスト全通過。

## 5. 落とし穴

- `formation()` は既存ブラウザテストが多数依存（`data-action="deploy"`・`toggledeploy`・`up/down/front`・`fire`）。**action 名と data 属性は変えない。**
- `UI.set()` の scene 推定（既知）。
- HUD を畳むとき `hud-records` を参照している CSS/テストがある。
- 人物の詳細は**応募者（名簿にいない）にも**開く。`uid` が無い応募者は `data-index` で引く。
- 記録札の「去った者」は名前だけ（詳細は開かない。名簿にいないので）。
