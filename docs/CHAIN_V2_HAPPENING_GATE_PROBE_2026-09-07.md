# CHAIN V2 ハプニング条件・予備測定（2026-09-07）

## 結論

ハプニング発火条件の `chainDepth >= 3` をV2段数へ変える実装は、まだ採用しない。
固定した汎用戦略200ランをseed基3本で比較した範囲では、production（V2倍率・raw条件）と
V2条件案のラン結果は全600件で一致した。しかし全15戦略を含む母集団ではなく、
「影響がない」と判断できる測定ではない。

## 測定方法

`node tools/chain-audit.js --runs 200` を `CHAIN_SEED_BASE=1000 / 2000 / 3000` で実行した。
同一seed・同一入力で、倍率だけV2へ接続したproduction相当のCと、そこから
ハプニング条件だけV2へ変えたEを比較した。raw `chainDepth`、記録、演出閾値は変えていない。

## 結果

| seed基 | 追加行動候補 | 条件の真偽が変化 | production C → 比較案 E |
|---:|---:|---:|---:|
| 1000 | 230 | 9（3.9%） | クリア46.0% → 46.0% |
| 2000 | 356 | 2（0.6%） | クリア51.5% → 51.5% |
| 3000 | 254 | 14（5.5%） | クリア43.5% → 43.5% |
| 合計 | 840 | 25（3.0%） | 全600ランで結果一致 |

条件判定が変わり得る場面は存在するが、この母集団では乱数抽選後の実発火や勝敗差に届かなかった。
これは切替の価値も安全性も証明しない。ハプニングは強さより「事件として伝わる頻度」が目的なので、
採否には全15戦略での対象別発火率と、実機での認知を別に見る必要がある。

## 次に進める条件

- 全15戦略で、有効ラン数を保証して対象ハプニング別の抽選機会・実発火数を測る
- productionと比較案で、倍率・入力・未完ラン処理が同一であることをassertする
- 数字だけで切り替えず、試遊で「連鎖に反応した事件」として読めるか確認する

それまではproductionのハプニング条件と演出閾値をrawのまま維持する。
