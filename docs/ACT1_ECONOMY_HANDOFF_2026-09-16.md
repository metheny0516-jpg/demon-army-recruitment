## 適用と契約

- 第一幕の `missionKind === "invade"` が対象。領土侵攻の単戦、前哨戦、本戦（制圧戦）それぞれの勝利決着に＋12G。二段階を両方勝てば合計＋24G。
- `suppress` の反乱鎮圧や部族を従える戦いは対象外。領土の `take` だけでは判定しない。
- 第二幕、略奪、訓練、巡回、防衛、撤退、判定負け、全滅敗北の入金は従来どおり。
- 税収・給与・食料・施設価格・敵の強さ・敵将賞金は据え置き。
- 札生成時に敵将による倍率処理を済ませ、その後に固定12Gを加える。倍率で固定額を膨らませない。
- 追加項目 `mission.invasionRewardBonus`（0/12）。`mission.reward` は作戦表示・結果表示・入金で使う総額。賞金は `reward - invasionRewardBonus` から算出。
- 出撃時に確定した額を決着まで持ち回る。第一幕最後の侵攻も＋12G、幕移行後に作る第二幕作戦には0G。
- 旧保存の候補札・選択札は移行時、旧保存の戦闘中データは決着時に一度だけ補完。既に項目があれば再加算しない。
- `pending.settled` を決着済みガードとして追加。同一pendingへの続行/撤退再送では報酬や給与を再処理しない。公開の手動決着入口も従来どおりpendingを消す。
- 完了済みの過去戦に遡って追加支給しない。旧版の画面で見た作戦報酬は、新版へのロード時に＋12Gへ更新される。

既存セーブに追加項目を読み足す後方互換の拡張で、既存項目の削除なし。battle.jsとUIファイルは変更していない。UIは既存のreward表示を使う。

## 再現手順

作業枝のリポジトリ直下で順に実行する（基点コミットの履歴が必要）。

```sh
node tools/test-act1-invasion-reward.js
ECON_BASE_REF=a2dc60dc15d2e3a1b34b8970f321751a4b791a8c ECON_OUTPUT=/tmp/act1-before.json node tools/measure-act1-economy.cjs
ECON_OUTPUT=/tmp/act1-after.json node tools/measure-act1-economy.cjs
```

比較はrun.jsだけを基点へ差し替える。将来dataや他のcoreが変わった後は、この作業コミットへ戻して再現する。新本線で実行した数値は別の測定として扱う。

設定：ランごとにlocalStorage初期化、U.rand=U.seeded(1〜30)、newRun後にgoblin/slime/kobold/orc/skeletonをrollApplicantで生成。全員出撃、金10/食料3/資材0、能力・給与は生成結果のまま。memberRecord/baseOfで通常の初期化。
採用・建設・借入・交換はしない。通常給与。防衛が出たら優先し、侵攻優先はinvade、略奪優先は3回raid後にinvade。事件は最初の選択肢。名簿が5人でなくなる、第二幕、敗北終了、最大12戦、操作上限100で停止。
これは合成した初期5人の自動進行で、通常採用過程・オーナーセーブ・人間のコマンド操作の再現ではない。「5人2G」の2Gの意味を仮定しない。

JSON各戦闘が正本。報酬reward、税tax、港port、敵将賞金bounty、戦闘中略奪loot、給与義務due、実払paid、利息interest、その他純収支other、現金差引delta、義務差引contractNet、前後残金gold0/gold1を保存。
`contractNet = delta + paid - due`。未払いを利益にしない。`between`は前戦決着後〜次戦直前の事件等の純収支で、その戦闘の報酬と分ける（事件内の収入/支出の個別明細までは採っていない）。
`win && remaining === 5`で5人生存を抽出。標本なしの平均はnull。firstSafeMarketは市場を買った後も次回給与を残せる最初の戦闘、購入実行ではない。

## 設計指針との整合

§15の主眼は普通の攻略・採用投資を成立させること（1/3/5）、明快な報酬（7）、必須の稼ぎ周回や管理操作を増やさないこと（8）。敵追随強化や人物の成功を打ち消す調整は加えない。残る調整は試遊で判断する。
