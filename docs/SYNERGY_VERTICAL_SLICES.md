# 代表3ビルド縦切り仕様

更新日: 2026-09-02

本書は `docs/SYNERGY_CONNECTION_AUDIT.md` で選んだ代表3系統を、コード実装へ入れる直前の仕様まで具体化する。
対象は「略奪経済」「暴食・飢餓」「戦死・蘇生」。最初から全特性を汎用化せず、この3系統が
発火、連鎖、再発火し、理由を表示できる最小契約だけを作る。

## 1. 共通原則

### 1-1. 連鎖の単位

一つの発火を `trigger` と呼び、以下を必ず持たせる。

| 項目 | 内容 |
|---|---|
| `eventId` | その戦闘内で一意のID |
| `type` | 攻撃、撃破、死亡、蘇生、召喚、資源獲得、資源消費、OVERKILLなど |
| `sourceId` | 発火させた人材・施設・作戦。自然消費の場合はシステム |
| `targetId` | 対象。存在しない場合は省略 |
| `parentEventId` | この発火を生んだ直前のイベント |
| `chainId` | 同じ連鎖に属するイベントの共通ID |
| `chainDepth` | 起点を1とした深度 |
| `amount` | ダメージ、金貨、食料などの量 |
| `tags` | `loot`、`food`、`death`、`overkill` などの反応用タグ |

既存の戦闘タイムラインを正本とする。別のシナジーログを並行して持たない。

### 1-2. CHAINの数え方

- プレイヤーの能力・施設・シナジーが、直前のイベントを原因として新しいイベントを発生させたら+1
- 通常攻撃そのものはCHAIN 1の起点になれるが、毎回の自動行動を連鎖継続とは数えない
- 同じ原因から複数対象へ分岐した場合、CHAIN表示は最大深度、発火回数は別集計にする
- 回復や防御でも別能力を呼べばCHAINになる。ダメージ量だけを評価しない
- 戦闘終了後の金貨・食料・建材への変換も、同じ `chainId` を引き継げる

### 1-3. 無限ループ防止

最初の実装では次を共通規則とする。

1. 1つの能力は同じ `chainId` 内で原則1回だけ発火
2. 「追加行動で発生したイベント」は、同名の追加行動能力を再発火させない
3. 伝播ダメージから新しい伝播は起こせるが、最大3回まで
4. 召喚ユニットは同じ戦闘中に召喚能力を持たない
5. 1戦闘のシナジーイベント上限は100件。到達時は計算を打ち切らず、追加発火だけを停止する
6. 乱数不使用の決定的ループをテストで検出する

この制限はプレイヤーへ細かな内部規則として見せない。「1戦闘1回」「連鎖3体まで」など、判断に必要な上限だけ説明する。

### 1-4. フェーズの境界

- 戦闘中の一時バフ、追加行動、召喚は `Battle.simulate()` 内で完結する
- 永続するG・食料・建材は、戦闘結果の `resourceChanges` を `run.js` が勝敗確定後に反映する
- 戦闘中に見せる獲得Gは予約値。原則として勝利時に確定し、敗北時は失う
- 前払い食料だけは出撃確定時に消費する。敗北しても戻らない
- 再起チェックポイントへ戻れば、出撃確定後の食料消費も巻き戻る

これにより戦闘エンジンへラン状態そのものを渡さず、現行の計算と進行の分離を守る。

## 2. 略奪経済ビルド

### 2-1. 狙う体験

弱いゴブリンの小さな攻撃が略奪を起こし、金貨獲得へ強欲持ちが反応し、追加行動とOVERKILLで
略奪回数が跳ねる。「火力を上げた結果、財布まで壊れた」という戦闘と経済の一体化を作る。

### 2-2. 最小パーツ

| パーツ | 種別 | 効果 | 未完成時の価値 |
|---|---|---|---|
| 《追い剥ぎ》 | 新特性 | 自身が敵へ初めてダメージを与えたとき、予約金貨1Gを略奪 | 単体でも小遣いになる |
| 《強欲》 | 新特性 | 同じ連鎖で初めて金貨を得たとき、攻撃力70%の追加行動 | 略奪作戦や他の金貨生成にも反応 |
| 《略奪者の連携》 | ゴブリン軍団の変換 | ゴブリン3体以上なら、撃破した攻撃でも予約金貨1G。従来倍率は+15%刻みへ縮小 | 種族寄せの入口を維持 |
| 《恐喝帳簿》 | 新施設 | 1戦闘の予約金貨が初めて3Gに達したとき、次の味方の攻撃+40% | 会計・給与ビルドでも使える |
| 《連鎖虐殺》 | 新特性 | 100%以上OVERKILLした余剰ダメージの30%を次の敵へ伝播。最大3体 | 純火力ビルドでも使える |

施設選択が未実装の間は、《恐喝帳簿》を固定の試験用ルールまたはシナジー効果として検証し、施設UIを先に作らない。

### 2-3. 発火例

`通常攻撃`
→《追い剥ぎ》で1G予約
→《強欲》が反応
→追加行動
→敵を撃破
→《略奪者の連携》でさらに1G
→OVERKILL 180%
→《連鎖虐殺》で次の敵へ伝播
→伝播で撃破
→3G到達時に《恐喝帳簿》が次攻撃を強化

表示上は最大 `CHAIN 8`。同じ《強欲》はこのchain内で再発火しないため、無限追加行動にはならない。

### 2-4. 完成時の壊れ方

- 通常勝利の報酬を上回る予約金貨を戦闘中に作る
- 低火力の多段攻撃が金貨と追加行動を増やし、最終的にOVERKILLへ届く
- 稼いだGが求人引き直し、厚遇、施設へ戻り、次の編成精度を上げる

上限は予約金貨ではなく発火回数で制御する。稼ぎが壊れる快感そのものは残す。

### 2-5. ヒントと表示

- 履歴書《追い剥ぎ》: 「敵に一太刀入れれば、少額を抜き取れる」
- 履歴書《強欲》: 「戦闘中の金貨獲得に反応する」
- 編成予告: 「金貨を作る者 2名／金貨に反応する者 1名」
- 戦闘表示: `追い剥ぎ +1G → 強欲 発動 → 追加行動`
- 戦果: 予約・確定金貨、略奪回数、追加行動数、最大OVERKILL

## 3. 暴食・飢餓ビルド

### 3-1. 狙う体験

通常は避ける食料大量消費と食料0を、自分から狙う。大食漢が軍団の負担ではなく燃料になり、
料理人が消費を抑えるだけでなく「食べさせて強くする」主役になる。

### 3-2. 戦闘前の食料契約

出撃確定時、選択中の戦闘員について `appetite` 合計から「戦闘糧食」を算出する。

- 基本消費 = `ceil(出撃隊appetite / 3)`
- 現在食料の範囲で消費し、出撃時に確定して減らす
- 消費できなかった量は `shortage` として戦闘開始イベントへ渡す
- 非戦闘員の生活消費は現行の戦闘後処理に残すが、二重計上を避けるため戦闘員分を除く

これは新しい管理画面を増やすためではない。編成した人材の食欲が、そのまま戦闘開始時の発火量になる。

### 3-3. 最小パーツ

| パーツ | 種別 | 効果 | 未完成時の価値 |
|---|---|---|---|
| 《大食漢》 | 新特性 | appetite+3。戦闘糧食を1以上消費できた場合、その戦闘の与ダメージ+25% | 単体で高コスト高火力 |
| 《魔界料理人》 | 前職反応の新特性 | 戦闘糧食1消費につき、最もappetiteが高い味方の与ダメージ+8%（最大80%） | 普通の編成でも食事をバフへ変換 |
| 《暴食の宴》 | 新シナジー | 1回の出撃で食料を4以上消費すると、最も遅い味方がラウンド1終了時に追加行動 | 大食い2〜3体で狙える中間目標 |
| 《飢餓の悪魔》 | 新特性 | 戦闘糧食の支払いで備蓄が0になった場合、全軍与ダメージ×2。ただし被ダメージ+30% | 食料0を危険な勝ち筋に変換 |
| 《巨大厨房》 | 新施設 | 戦闘糧食による能力の加算量を2倍。ただし消費量+1 | 暴食を先鋭化する大型規則 |

### 3-4. 発火例

`出撃確定`
→戦闘糧食5を消費
→《大食漢》2名が強化
→《魔界料理人》が消費5へ反応し、最も大食いの味方を+40%
→《暴食の宴》成立
→備蓄0に到達
→《飢餓の悪魔》で全軍×2、被ダメージ増加
→ラウンド1終了時に追加行動

食料0は強力だが、敵を倒し切れなければ被ダメージ増加と戦闘後の生活部門不足が残る。

### 3-5. 完成時の壊れ方

- 普通なら維持不能な大食い編成ほど初動火力が上がる
- 食料をぎりぎり0に合わせる編成・作戦選択が生まれる
- 料理人が非戦闘職ではなく、最大火力を決めるキーパーツになる
- 短期決戦では壊れるが、寄り道や連戦では食料回復手段が必要になる

### 3-6. ループ防止と境界

- 食料消費への反応は出撃確定時に1回だけ解決する
- 追加行動は食料を再消費しない
- 巨大厨房は「効果量」を倍化し、同じ能力を2回発火させない
- 食料0判定は消費処理後の遷移時のみ。すでに0の状態からは発火しない
- 再起で出撃前へ戻った場合は食料も復元する

### 3-7. ヒントと表示

- 履歴書《大食漢》: 食欲値と「食べられれば強い」を併記
- 履歴書《魔界料理人》: 「食料消費が多い軍団ほど腕を発揮」
- 編成予告: `戦闘糧食 5消費 → 備蓄0／暴食の宴・飢餓 発火見込み`
- 戦闘開始: 食事の因果を一括表示してから短いカットイン
- 戦果: 消費食料、食事由来倍率、追加行動、食料不足リスク

## 4. 戦死・蘇生ビルド

### 4-1. 狙う体験

永久退場という本物の損失を消さず、死ぬこと自体を連鎖の起点にする。
「この味方は死なせても戻せる」「戻せなければ本当に失う」という本作固有の緊張を作る。

### 4-2. 最小パーツ

| パーツ | 種別 | 効果 | 未完成時の価値 |
|---|---|---|---|
| 《墓守》 | 新特性 | 味方が死亡するたび魂を1獲得。戦闘終了まで保持 | 死亡を後続能力用の資源へ変換 |
| 《死霊術》 | 既存特性の構造化 | ラウンド終了時、死亡した味方1体を1戦闘1回蘇生 | 現行どおり退場保険になる |
| 《墓地》 | 新施設 | 最初に死亡した味方をラウンド終了時に骸骨従者として一度召喚 | 死霊術師がいなくても死亡を戦力化 |
| 《魂の徴収》 | 新特性 | 味方が蘇生・召喚されたとき、魂を1消費して全アンデッド+20%（戦闘中累積） | 蘇生と召喚の受け手になる |
| 《殉職手当》 | 新シナジー | 蘇生した味方が撃破すると予約金貨2G。最終的に戦死した場合は得られない | 死亡系を略奪経済へ接続 |

### 4-3. 召喚ユニットの最小契約

骸骨従者はロスターへ保存しない戦闘専用ユニットとする。

- 元の死亡者とは別ID
- HPは元の最大HP30%、攻撃は元の攻撃50%、速度は固定
- 特性、給与、忠誠、戦功、前職を持たない
- 出撃上限5体には数えないが、同時存在は1体まで
- 戦闘終了時に消滅し、戦死者名簿へ入らない
- `summon` イベントに完全なSnapを含め、レンダラが途中追加できるようにする

最初の召喚は既存の骸骨画像を使用し、新規2D素材を前提にしない。

### 4-4. 発火例

`味方Aが死亡`
→《墓守》が魂1獲得
→ラウンド終了時、《死霊術》でAが蘇生
→蘇生イベントへ《魂の徴収》が反応
→魂1消費、アンデッド全体+20%
→次に味方Bが死亡
→《墓地》が骸骨従者を召喚
→召喚へ《魂の徴収》が反応
→蘇生したAが敵を撃破
→《殉職手当》で2G予約

### 4-5. 全滅境界

現行戦闘は一方が全滅した時点でラウンド終了処理へ入らない。死亡ビルドのため、次へ変更する。

- 全滅時に `onRoundEnd` 全体を実行するのではなく、「即時敗北前の救済フック」だけを1回解決する
- 死霊術、執念、墓地召喚のいずれかでプレイヤー側が1体以上戻れば戦闘継続
- 何も戻らなければ現行どおり敗北
- 敵側も同じ契約を利用できるが、初期コンテンツでは使用しない
- 救済フックは1ラウンド1回。復活後に再全滅しても、未使用能力だけが反応できる

### 4-6. 完成時の壊れ方

- 味方が倒れるほどアンデッド軍団の火力が増える
- 一度全滅したように見えて蘇生・召喚から逆転する
- 蘇生者の撃破が金貨へ変わり、別の略奪ビルドへ橋がかかる
- ただし蘇生枠を超えた死亡者は本当に永久退場し、雑な自爆はランを壊す

### 4-7. ループ防止

- 同じ個体の死亡は、蘇生後に再死亡すれば別イベントとして数える
- ただし《墓守》の魂獲得は同じ個体につき1戦闘1回
- 《死霊術》と《墓地》は各1戦闘1回
- 召喚ユニットの死亡は魂を生成しない
- 《魂の徴収》は最大5スタック
- 蘇生者の撃破による殉職手当は1体につき1回

### 4-8. ヒントと表示

- 編成予告: 「死亡へ反応 2／蘇生 1／召喚 1」
- 死亡時: `A死亡 → 墓守：魂+1`
- ラウンド終了: `死霊術 → A蘇生 → 魂の徴収 → アンデッド+20%`
- 全滅救済は通常蘇生より強い暗転・カットインを使う
- 戦果: 死亡回数、最終戦死者、蘇生、召喚、魂獲得・消費、救済回数

## 5. 3系統をつなぐ橋

3ビルドを閉じたセットにしない。最低限、以下の横断接続を持たせる。

| 起点 | 橋 | 接続先 |
|---|---|---|
| 略奪経済 | 稼いだGで食料を買う、厚遇する | 暴食・忠誠 |
| 略奪経済 | OVERKILLで敵を骸骨化 | 戦死・召喚 |
| 暴食 | 大食いの高火力でOVERKILL | 略奪・伝播 |
| 飢餓 | 被ダメージ増加で味方死亡 | 戦死・蘇生 |
| 蘇生 | 蘇生者の撃破で殉職手当 | 略奪経済 |
| アンデッド | 食事不要で食料を温存 | 食料0を狙うタイミング調整 |

横断能力は最初からすべて実装しない。《殉職手当》と《連鎖虐殺》を最初の橋として優先する。

## 6. 実装順

1. 共通イベント語彙、親子関係、CHAIN集計だけを追加（第一段階完了）
2. 既存の攻撃・撃破・死亡・蘇生を新語彙へ写す。挙動は変えない
3. 略奪経済を実装し、追加行動と予約Gを検証
4. 戦闘前食料契約を実装し、暴食・飢餓を追加
5. 全滅救済フックと召喚契約を追加し、戦死・蘇生を実装
6. OVERKILL計算と伝播を追加
7. 戦果パネルへCHAINと非ダメージ貢献を追加
8. 戦闘シーンへ因果表示を追加

OVERKILLを略奪経済より後にしているのは、最初に連鎖基盤と予約Gを単独検証するため。
最終的な体験ではOVERKILLを3系統すべてへ接続する。

## 7. セーブ互換

- 既存セーブに新フィールドがなくても、特性・施設・統計は空または0として扱う
- 戦闘タイムラインは保存対象ではないためイベント契約追加による移行は不要
- 新施設が未選択なら現行施設レベル補正をそのまま使う
- 戦闘前食料消費は新しい処理なので、旧セーブ再開時も出撃確定前なら通常どおり計算する
- 魔界史のCHAIN、OVERKILL、略奪、蘇生統計は欠損時0として表示する

## 8. 実装開始の判定

3系統とも、最小パーツ、未完成時の価値、発火順、壊れ方、無限ループ防止、表示、セーブ互換を定義した。
次は本書の実装順1「共通イベント語彙、親子関係、CHAIN集計」のコード設計へ進める。

ただし、以下は実装中の測定で調整してよい。

- 倍率、予約G、食料閾値などの数値
- CHAIN表示のテンポ
- 召喚ユニットの能力値
- 1戦闘のイベント上限

能力の因果関係、三部門を独立ゲームにしないこと、壊れビルドを許容することは変更しない。
