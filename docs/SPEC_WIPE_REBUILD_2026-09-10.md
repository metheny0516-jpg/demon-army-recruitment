# 仕様：全滅は敗北であって終了ではない——再建と再起の縮小（2026-09-10）

迷ったら末尾「未決」を見て、無ければ**いちばん小さく、いちばん今の動作に近い**ほうを選び、コミットメッセージに書く。
担当：CodeX の種族技コミットC（`run.js` の決着処理）が作業ブランチに入ってから、空いている実装セッション（Opus 想定）。ブランチ `codex/wipe-rebuild` か `claude/wipe-rebuild`。

## 0. 一文で

**出撃隊が全滅したら、出撃した者は戦死し、留守番と金で軍団を建て直す。** 戦死者は履歴と遺物を残し、次の面接に縁の者が来る（継承がそのまま効く）。再起（時の巻き戻し）は「軍団が空で、雇う金も無い」ときの最後の手段だけに縮める。判定負けは撤退と同じ扱い（倒れた者は担いで帰る）。

## 進め方（オーナー指示 2026-09-10・全仕様共通）

- 速度優先。軽いモデルのサブエージェントを2〜10体並列（調査・ファイル単位の編集・テスト・台詞）。担当ファイルを重ねない。統合とコミットは親。
- 重い処理は直列（sim・run-all・browser-tests は一度に一つ。4コアなら sim 3本並列は可、browser-tests と同時は不可）。
- `run.js` と `battle.js` は同じコミットで触らない。**この仕様は battle.js を触らない。**

## 1. 目的と、やらないこと

目的：
- 負けが歴史になる。「ガロたちは神殿騎士団に敗れ、戻らなかった」が魔界史と面接に残る。
- 継承（遺物・縁の者・去った者の一覧）が、いちばん多い離脱の形＝敗北で発火する。今は勝ったときの戦死でしか発火しない。
- 再起の巻き戻しが物語を消すのをやめる。

やらないこと：
- 捕虜・行方不明・後日の帰還。LP の仕様で扱う。
- 王国の反撃（防衛戦）。次の仕様。
- 開幕3日間の作り直し（2.4 で最小限だけ触る）。
- 魔界史の主要記録の追加（設計憲法 第11節）。

## 2. ルール

### 2.1 出撃隊の全滅（`result.wipe === "player"`）

決着（`settleContinue` の敗北側）で：
- 出撃していた軍団員（傭兵・召喚物を除く）は**全員戦死**。`Game.recordDeparture(m, "fallen", { army })` を通す（継承と同じ入口。遺物・履歴・縁の者は自動で付いてくる）。`processCasualties` と同じく名簿と出撃リストから外す。
- 傭兵は今と同じ（欠員にならず名簿にも載らない）。
- 報酬なし。略奪金貨没収。征服は進まない。警戒度 `+alertDelta`（無ければ +1）。**撤退と同じ**。
- 給与：出撃隊は死んでいるので払わない。留守番の手当は払う。留守番の仕事（食料・建材）とツケは今までどおり。
- `st.turn += 1`、`st.missionOffers = []`、`st.fallenTotal` 加算、`st.wipeCount = (st.wipeCount||0)+1`。
- フェーズは **`"result"`**（`"defeat"` ではない）。`lastBattle.wiped = true`。結果画面は見出し「全滅」（3.1）。
- その後は通常の流れ（`afterResult` → 施設／事件／面接）。**面接で縁の者が来る**（複数戦死なら、最も戦歴の長い者の縁）。

### 2.2 判定負け（30ラウンド経過で負け、全滅ではない）

撤退と同じ結末にする（`settleRetreat` を流用。`retreated` ではなく `lastBattle.lostOnPoints = true`）。倒れていた者は担いで帰る＝負傷。報酬なし。結果画面の見出しは「敗走」。文言：「{army}に押し返された。{担がれた者}は担いで戻った」。

### 2.3 軍団が空になったとき（再建できるか）

決着後（2.1 のあと、`afterResult` の前）に判定：
- 名簿に誰か残っていれば**続く**。留守番だけでも続く（次の面接で出撃隊を作る）。
- 名簿が空で、所持金で応募者を1人以上雇える（`Game.hireCost()`、無料枠があれば0）なら**続く**。面接に進む。モルモ「魔王様、軍は……全員です。ですが金庫は生きていマス。募集を、かけ直しましょう」。
- 名簿が空で、雇う金も無い → **ここでだけ再起を提示**（2.5）。再起も使い切っていれば `"gameover"`（今の `concede` と同じ流れで魔界史へ）。

### 2.4 開幕3日間の防衛戦（`openingPrototype`）

同じ規則を適用する。開幕で全滅すると名簿が空になりやすいが、2.3 のとおり金があれば面接へ進める。**開幕の特別扱いは足さない**（未決 U1）。

### 2.5 再起の縮小

- `st.phase = "defeat"` になるのは **2.3 の「名簿が空で金も無い」ときだけ**。それ以外の敗北で `"defeat"` にしない。
- `retry()` の中身は今のまま（チェックポイントへ戻す、金半減、1回）。
- `defeat` 画面の文言を「全員を失い、金庫も空だ。時を巻き戻すか、この歩みを魔界史に刻むか」に変える。
- **未決 U2**：再起を完全に消すか。既定：残す（最後の手段として）。

### 2.6 チェックポイントは今のまま

`saveCheckpoint()` の場所は変えない。再起が縮まるので実質使われなくなるが、消すのは U2 の後。

## 3. 表示

### 3.1 結果画面（全滅）

見出し「全滅」（撤退の見出しと同じ場所・同じ作り。`set(html, "report")` で scene を明示）。
本文一行目：「{army}に敗れた。{name1}、{name2}……は戻らなかった。」
二行目：留守番がいれば「城には {n}人が残っている」。遺物が残れば「{name}の{relic}が蔵に残った」。名簿が空なら「城に残る者はいない。金庫に {gold}G」。
以下は今の `notes`（留守手当・留守番の仕事・ツケ）。

### 3.2 モルモの報告（`main.js battleReport()`）

`lastBattle.wiped` なら表情 worried、「{army}に……全員、戻りませんでした。{留守番がいれば：城の者で、立て直しましょう／いなければ：募集を、かけ直しましょう}」。
`lostOnPoints` なら「押し返されました。{担がれた者}殿は担いで戻りました」。
既存の「撃退しました！」の分岐に**入れない**（撤退のウソ報告と同じ穴）。

### 3.3 面接画面

軍団史の行（既存）に「最後は {name}（戦死、{army}）」が出るので追加不要。名簿が空のときの面接には「軍団は全滅した。ここから建て直す」の一行と、蔵に遺物があれば「🏺 蔵に {n}品」。

## 4. 契約（追加されるもの）

- ラン状態：`st.wipeCount`。`lastBattle.wiped`（bool）、`lastBattle.lostOnPoints`（bool）。
- `st.phase === "defeat"` の意味が変わる：**「軍団が空で金も無い」だけ**。`defeat` 画面と `retry / concede` はその前提で動く。
- `Game.settleContinue` の敗北側が `recordDeparture` を通す。`Game.canRebuild()`（名簿あり or 雇える金あり）を足し、`afterResult` の前に呼ぶ。
- battle.js は触らない。`result.wipe` は既に `"player" | "enemy" | null` で出ている。

## 5. 受け入れ条件

### 5.1 `tools/test-wipe-rebuild.js`（新規）

ハーネスは `tools/test-retreat-run.js` を写す（名簿は自前。`U.rand` 固定で全滅する戦闘を作る：味方HP1×2、敵HP高・攻撃高）。
- 全滅 → 出撃した2人が `st.departed` に `fallen` で入り、名簿から消え、留守番は残る。`phase === "result"`、`lastBattle.wiped === true`、報酬0、警戒度+。

- 判定負け（両軍生存で30ラウンド）→ `lostOnPoints`、倒れていた者が `injured === 1` で名簿に残る。

## 7. 落とし穴

- **決着処理は `settleContinue` / `settleRetreat` の二つ**。全滅は `settleContinue` の敗北側。判定負けは `settleRetreat` の流用。三つ目の経路を作らない。
- **`recordDeparture` を通す**。名簿から消すだけだと遺物も縁の者も出ない（今の敗北がまさにそれ）。
- **`UI.set()` の scene 推定**。見出し「全滅」を足すなら第2引数で `"report"` を明示。
- **`main.js battleReport()` の既定分岐は「撃退」**。`wiped` / `lostOnPoints` / `retreated` を先に見る。
- **sim・テストは引数なし `deploy()`**。UI 経由と同じ結末になること。
- **チェックポイントの保存位置**は変えない。変えると再起の意味が二重に変わる。
