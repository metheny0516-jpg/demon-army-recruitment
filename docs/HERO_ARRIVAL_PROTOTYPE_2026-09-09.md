## 0. 何のための試作か

**「人を採って仕事を任せたら、直接命令していない出来事が別の出来事につながった」**
と実際に感じられるかを、触って確かめるためだけのもの。
核はモルモの一言：**「魔王様、勇者です。先ほどまで、うちで飲んでいた方です」**

設計書 v0.3 ではない。本編の改修計画でもない。

## 1. 起動方法

`hero-arrival.html` をブラウザで開くだけ（本編の `index.html` と同じくローカルファイルで動く）。

```
file:///…/demon-army-recruitment/hero-arrival.html
```

URLパラメータ（比較用。画面上のボタンでも切り替えられる）:

| 指定 | 意味 |
|---|---|
| `?cond=B` | 相手は休憩中。安全と思った店で一杯飲む（既定） |
| `?cond=A` | 相手は任務優先。勤務中は飲まない |
| `?seed=5` | 同じ条件を別の乱数で見る |

**本編のセーブ・魔界史・戦績・音量・戦闘速度・KPIには一切書き込まない。**
このページの `localStorage` は `heroproto_` 名前空間へ丸ごと差し替えてある。

## 2. 試し方（この順で触ると差が見える）

### B：モグに店を任せる ← 今回いちばん見てほしいもの

1. `?cond=B` で開く。モグを **「城下の店」** で雇う。リゼとホネ吉は **「守備」** で雇う。
2. 「任せて進める」→ 最初の勤務でモグが酒を仕込む。
3. もう一度「任せて進める」→ **旅の方**が店に来て、モグが一杯すすめ、相手が飲む。
   この時点で画面に「勇者」「アレン」の語は出ない。モルモも「旅の方」としか言わない。
4. もう一度「任せて進める」→ 門で身元が分かり、モルモが報告する。
5. 敵情に「酔い（速度-4）」が出ている。そのまま迎撃する。
6. 決着画面の「何が、何につながったか」に、生産→提供→飲酒→迎撃の台帳がそのまま出る。

### 同じ手順で、結果が変わることの確認

| 変えるもの | 起きること |
|---|---|
| `?cond=A` にする | 同じモグが同じ酒を勧め、断られる。樽は残る。普通に迎撃して終わる |
| モグを「守備」に置く | 酒はできない。店に置くのが条件で、モグを採ったこと自体は条件ではない |
| レナを「城下の店」に置く | 酒はできない。「普通に店を開けた」で終わる |
| モグに「販売のみ（外の者に振る舞うな）」 | 酒はできるが提供しない。裏で振る舞う罰はない |
| ガンツを「門番」から「守備」へ移す | 身元が確認できず、「飲んでいた方です」は出ない（飲んだ事実自体はある） |
| 誰も城下に置かない | 誰も客に会わない。平穏な勤務として1行にまとまる |

### A：普通の勇者迎撃

1. モグを採らず、リゼ・ホネ吉・レナを守備で雇う。
2. ガロを **「近郊警戒」**（準備段階でだけ選べる）へ送る → 生還すると小隊長になり、HPと攻撃が実際に上がる。
3. 到着後、迎撃隊を選ぶ。**選んだ順が並び順**で、先頭が狙われやすい。
   ガロを先頭にした回とガンツを先頭にした回で、被弾する人物と持ちこたえ方が変わる。
4. 決着画面は「誰が働いたか」「誰が帰らなかったか」を事実として出す。

## 3. 実装で決めたこと

- 状態は `src/prototype/hero_arrival_world.js`（DOM非依存・Nodeから読める）だけが持つ。
- 戦闘は既存 `Battle.simulate` をそのまま呼ぶ。試作用の戦闘計算・CHAIN・新機構は足していない。
- 起きたことは全部 `facts` 台帳に積む。**報告文も敵情への反映も台帳からしか作らない。**
  だから「事実と食い違う報告」が構造的に出せない。決着画面で台帳そのものを見せている。
- 人物名で分岐する条件を書かない。酔いの反映も
  「`consume` で `drunk` が付いた ID」を引くだけで、アレンという名前を見ていない。
- 一マス移動、T管理、集合操作、遠隔バフは作っていない。
- 試作の敵数値（`HERO_PARTY`）は試作側が持つ。`src/data/enemies.js` は変更していない。

## 4. 測ったこと（`node tools/sim-hero-arrival.js 300`）

| 条件 | 勝率 | 戦没 |
|---|---|---|
| 標準5名・ガロ先頭・育成なし | 79% | 2.86人/戦 |
| 標準5名・ガロ先頭・育成あり | 87% | 2.63人/戦 |
| 前衛をガンツへ | 98% | 1.98人/戦 |
| 標準5名・相手が酒を飲んでいる | 94% | 2.26人/戦 |
| リゼを外して職人モグを入れる | 24% | 4.56人/戦 |
| 4名で挑む | 0% | — |
| 近郊警戒（ガロ単独）の生還 | 96% | — |

読み方：**普通に組めば普通に勝てる（79%）**。育成で+8pt、酒で+15pt、前衛順で+19pt。
どれも「差は出ている」が、**それが手応えとして気持ちいいかは未測定**。

## 5. 未検証事項（試遊で見てほしいところ）

1. **発見が伝わるか。** 「旅の方」→門で判明→敵情に酔い、の順で驚きが来るか。
   それとも先に分かってしまうか。モルモの一言の間・表情・テンポは調整していない。
2. **前衛順が効きすぎる。** ガンツ先頭が98%で、ほぼ正解になっている。
   「考えたくなる」ではなく「答えがある」状態かもしれない。
3. **戦没が多い。** 勝っても平均2.9人が帰らない。設計の「送り出した顔ぶれが帰ってくる」と
   合っていない可能性がある。数値を緩めるか、敗北の見せ方を変えるかは試遊後に決めたい。
4. **職人を入れると24%。** 必敗ではないが痛い。「弱くても働けるか」の答えとして妥当か。
5. **酔いの強さ（速度-4）。** 設計案は-2だったが、-2では勝率差がほぼ出なかったので-4にした。
   本番値ではない。速度低下という表現自体が地味すぎないかも見てほしい。
6. **台帳の見せ方。** 決着画面に内部の動詞（`produce` / `offer` / `consume`）を出している。
   検証のためであって商品画面の案ではない。
7. **区間が3つで足りるか。** 準備→勤務→城下→到着。短すぎて「任せている」感じが薄いか。
8. **レナの扱い。** 元同僚という関係を持っているのに何も起きない。
   対照として正しいのか、バグに見えるのか。
9. **繰り返し遊びたくなるか。** 条件A/B・seed・仕事の組み合わせを変えて2回目を触りたくなるか。
