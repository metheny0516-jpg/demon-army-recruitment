# 仕様：継承の最小仕様と魔王軍レベル（2026-09-10）

実装担当者向け。この文書と `HANDOFF.md` §0・§2 だけで始められるように書いてある。
迷ったら末尾「未決」を見て、無ければ**いちばん小さく、いちばん今の動作に近い**ほうを選び、コミットメッセージに書く。

## 0. 一文で

**人は消えるが、その人が軍団に残したものは消えない。** 永久に離脱した者は履歴を残し、目立った者は「遺物」（癖が一つ宿った品）を残す。次の面接には故人と縁のある応募者が混ざり、遺物を継いだ者に癖が移る。応募者の水準は「魔王軍レベル」（既にある `campaignLevel()`）に従って上がる。

継承は**軍を強くするための仕組みではなく、物語を続ける装置**。継いだ者は同じ人物にならない。ヘタレならヘタレのまま。

## 2. 魔王軍レベル

### 2.1 いまあるもの

`Game.campaignLevel()` ＝ `max(conquest + 1, ceil(turn × 0.75))`、上限8。`rollApplicant()` がこれで応募者の能力を `× (1 + 0.12 × (level − 1))` し、種族の出現率（tier）も動かしている。**新しいパラメータは作らない。これを「魔王軍レベル」と呼び、伸びを直す。**

### 2.2 直すこと

- 敵は段階1→4でHP14→38（約2.7倍）だが、応募者はレベル4で1.36倍。ここを詰める。
  応募者の倍率を `1 + k × (level − 1)` の `k` で調整し、**「レベルLの応募者の平均戦力が、段階Lの敵1体の 70〜80%」**を目安にする（新人がそのまま最前線に立てはしないが、昇進1回で追いつく）。`k` は data に置く（`MONSTER_RULES.applicantGrowth` のような1か所）。最初の値は 0.22 から試し、sim で決める（6.1）。
- HUD に「魔王軍 Lv.N」を小さく出す（今は内部値で見えない）。応募者の札には出さない（数字で選ばせない）。
- 揺れ（0.85〜1.15）は今のまま。

### 2.3 敵も魔王軍レベルに連動させる（オーナー決定 2026-09-10）

今は `buildMission()` が敵の段階表を **征服段階（`st.conquest`）だけ**で引いている。だから略奪・鎮圧を繰り返せば、応募者だけ強くして敵は据え置きにできる。
これを **魔王軍レベル**で引く：`baseIndex = clamp(armyLevel − 1 + type.enemyTierOffset, 0, 7)`。征服段階は「どこまで攻め落としたか（クリア判定）」の意味だけ残す。
時間が経つほど敵も強くなる。これが「王国が黙っていない」の一番小さい形で、次の仕様（王国の反撃）の土台になる。

ただし今の式 `max(conquest + 1, ceil(turn × 0.75))` はターン10で8（最終段階）に達する。慎重な戦略は13戦以上戦うので、
このまま敵に使うと征服2のまま聖騎士団が来る。**ターン側の係数を緩める**：`max(conquest + 1, ceil(turn × 0.5))` から試す
（ターン14で8）。係数は data に置く（`MONSTER_RULES.levelPerTurn`）。決めるのは sim（6.1）：
「略奪4回→侵攻」「慎重経営」のクリア率が他の戦略より**極端に上下しない**こと。略奪を繰り返す戦略が今より不利になるのは狙いどおりで、
ゼロになるのは締めすぎ。

## 3. 離脱の記録

### 3.1 永久離脱の4種

| cause | いつ | 既存の処理 |
|---|---|---|
| `fallen` 戦死 | `processCasualties`（続行して倒れたまま終わった） | `st.lastFallen` / `fallenRoll` |
| `fired` 解雇 | `Game.fire(uid)` | 名簿から消すだけ |
| `deserted` 逃亡 | `processDepartures`（愛想を尽かして去った） | 名簿から消すだけ |
| `retired` 引退 | **新規**：負傷から戻る前にもう一度担がれた者（撤退で2回連続 `carried`）は引退する。「もう戦えない」 | 無し |

4種すべてを `st.departed[]` に積む（3.2）。傭兵（`mercenary`）と召喚物は対象外。

### 3.2 個人の履歴（`st.departed[]` の1件）

```js
{
  uid, name, race, tplId, job, traits: [...], rankId, merit,
  cause: "fallen" | "fired" | "deserted" | "retired",
  day, turn, army,                 // army は戦死・引退のときの相手。解雇・逃亡は null
  record: { battles, wins, downed, carried, late, ate },   // 3.3 の個人カウンタの写し
  relicId: null | "relic_12"       // 遺物を残したなら（4.1）
}
```

### 3.3 個人カウンタ（名簿の各員に持たせる）

痕跡の器（`src/core/traces.js`、別仕様で作成中）が入るまでの**つなぎ**として、名簿の各員に小さなカウンタを持たせる。器が入ったら、これは器の集計で置き換える（置き換えは別タスク。今はカウンタで進める）。

`m.record = { battles: 0, wins: 0, downed: 0, carried: 0, late: 0, ate: 0 }`。旧セーブは `migrateState` で補う。
更新は**決着処理の中**（`settleContinue` と `settleRetreat` の両方。`deploy()` の途中に書くと引数なし呼び出しと UI 経由でずれる）：
- 出撃した全員 `battles++`。勝てば `wins++`。
- `contribution` の `survived === false`（続行）または `injured`（撤退で担がれた）→ `downed++`。担がれた者は `carried++`。
- `contribution.late > 0` → `late++`。大食漢の食事は `contribution.ate`（battle.js 側に無ければ**この仕様では数えない**。battle.js は触らない）。

## 4. 継承

### 4.1 遺物（形ある継承）

**条件**：離脱した者が「目立った者」なら遺物を1つ残す。目立った者＝ `record.battles >= 6` または `rankId !== 兵卒` または `record.carried >= 1`（担がれて帰った経験がある）。解雇・逃亡でも条件を満たせば残す（「クビにした奴の斧が倉庫に残っている」も物語）。

**中身**：離脱者の特性のうち、**種族固有でないもの**（テンプレートの `fixedTrait(s)` に含まれない特性）から1つ。候補が無ければ遺物は残さず、履歴だけ残る。
名前は `${name}の${TRAITS[traitId].relic || "兜"}`。`relic` は `traits.js` に足す短い名詞（酒好き「杯」、大食漢「弁当箱」、改造癖「工具袋」、卑怯者「短刀」、強欲「財布」、怖がり「盾」、見栄っ張り「兜」…）。無い特性は「兜」。

```js
st.relics.push({
  id: "relic_12", name: "ガロの杯", traitId: "drunkard",
  from: { name: "ガロ", race: "オーク", cause: "fallen", army: "神殿騎士団", turn: 7 },
  holderUid: null            // 誰も持っていなければ蔵にある
});
```

**効果**：遺物を持つ者に `traitId` の特性が付く（既に持っていれば何も起きない。それも「らしい」）。持ち主が離脱したら遺物は蔵へ戻り（`holderUid = null`）、特性は外れる。**遺物1つにつき持ち主1人。同じ人物が2つ持つのは可。**
持ち主の札に「🏺 ガロの杯」を出す。特性一覧では遺物由来の特性に「（ガロの杯）」を添える。

**決裁**：遺物の受け渡しは編成画面の「蔵」パネルで魔王が決める（「誰に渡す」「蔵に戻す」）。自動では渡さない。ただし縁の応募者（4.2）が「持って来た」場合だけ、採用時点で持っている。

### 4.2 縁の応募者（人物関係の継承）

離脱が起きた**次の面接**で、応募者のうち1人が「縁の者」になる（`genApplicants` の中。`legacyReturn` と同じ位置で差し替える。両方あるなら別々の枠）。

- `applicant.bond = { name: "ガロ", cause: "fallen", kind: "admirer" | "kin" | "avenger" | "rumor" }`
- `kind` は cause で決まる：戦死→ `admirer`（憧れ）か `kin`（縁者）か `avenger`（仇討ち。相手の army を覚えている）、解雇→ `rumor`（「あいつがクビになったと聞いて枠が空いたと思った」）、逃亡→ `rumor`、引退→ `admirer`。
- **志望理由（`motive`）**を `bond` 用のプールから引く（`src/data/monsters.js` か新規 `src/data/bonds.js`。`{name}` `{army}` を差し込む。各 kind 4本以上）。例：「{name}隊長に憧れて」「父がこの軍で死んだ。{name}と同じ戦場で」「{army}に借りがある。{name}の分も」「{name}がクビになったと聞いた。枠が空いたんだろ」。
- 種族は故人と同じ種族を 60%、それ以外は通常の抽選。能力は魔王軍レベルどおり（**強くしない**）。
- 故人の遺物が蔵にあれば 50% で「持って来た」（`relicId` を持ち、採用時に `holderUid` になる）。
- モルモの面接の一言：「……この者、{name}殿の話ばかりしますネ」「{name}殿の{relic}を持っていマス。どこで拾ったのやら」。面接画面の応募者の札に `bond` の印（「🕯 {name}の縁」）。

### 4.3 継いだ者は同じ人物にならない

- 能力は応募者の水準（2.2）。特性は遺物の分だけ増える。
- 遺物を持った縁の者の職名に「二代目」を足すのは**表示だけ**（`job` を変えない。札の表示で `（二代目{name}）` を添える）。
- 「二代目が初陣で逃げた」は仕組みでは作らない。怖がり等の候補特性が実装されれば勝手に起きる。

### 4.4 履歴の見せ場

- 魔界史（`endRun` の record）に `departed` の要約（名前・種族・cause・battles/wins・遺物名）を足す。主要記録は増やさない（設計憲法 第11節）。表示は既存の魔界史画面の下に「去った者たち」の一覧（1人1行）。
- 面接画面の上に「軍団史」1行：「これまでに {n}人が去った。最後は {name}（{cause}、{army}）」。

### 4.5 軍団の文化（表示のみ）

痕跡の集計から**2軸だけ**導く。**数値・確率・抽選には一切効かせない。**
- `retreatCount`（撤退回数）と `fallenTotal`（戦死者数）の比：
  - 撤退 ≥ 戦死×2 かつ撤退 ≥ 2 → 「生きて帰るのが武勲」
  - 戦死 ≥ 撤退×2 かつ戦死 ≥ 2 → 「仲間を置いて逃げない」
  - どちらでもない → 表示しない
- 出るのは面接画面の「軍団史」の行と、モルモの出撃前報告の一言だけ（「うちの軍風は『生きて帰るのが武勲』デス。無理はなさらず」）。
- 縁の応募者の `motive` プールを文化で切り替えるのは**未決 U3**（既定：しない）。

## 6. 受け入れ条件

### 6.1 魔王軍レベル（sim）

`node tools/sim.js 50` を実装前後で各3回。目標：平均クリア率が実装前（直近 51%前後）から **±8pt 以内**。応募者を強くしたぶん上がりすぎたら `k` を下げる。敵の連動（2.3）で下がりすぎたら `levelPerTurn` を下げる。**2.2 と 2.3 は別々に sim を取る**（応募者だけ／敵だけ／両方）。どちらが効いたか分からない表は受け取らない。合わせて sim の「最大軍団」「戦死」が極端に変わっていないこと。数値はコミットメッセージと HANDOFF §0 に表で書く。

### 6.2 `tools/test-inheritance.js`（新規）

ハーネスは `tools/test-tinkerer-run.js` を写す（名簿は自前で作る）。`U.rand` / `U.chance` は要所で固定する。

- 戦死（続行で倒れたまま終了）→ `st.departed` に cause `fallen`、`record.battles` が出撃数と一致、`army` が入る。
- 解雇 → `fired`。逃亡（`processDepartures` を未払いで起こす）→ `deserted`。
- 撤退で担がれた者を、負傷が明ける前にもう一度担ぐ → `retired` で名簿から消える。
- `record.battles >= 6` の酒好きが戦死 → 遺物「{name}の杯」が `st.relics` に入り `traitId === "drunkard"`、`holderUid === null`。兵卒で5戦の者は遺物を残さない。種族固有の特性しか無い者は遺物を残さない。
- `Game.giveRelic` → 持ち主に特性が付く。`storeRelic` → 外れる。持ち主が離脱 → 蔵へ戻り特性が外れる。元から同じ特性を持つ者に渡しても特性は二重にならない。
- 離脱の次の `genApplicants` で応募者の1人に `bond` があり、`motive` に故人の名が入る。`legacyReturn` と同時でも両方いる（枠が違う）。遺物が蔵にあり `U.chance` を true に固定すれば `relicId` を持って来て、採用で `holderUid` になる。
- 文化の判定：撤退4・戦死1 →「生きて帰るのが武勲」。戦死4・撤退1 →「仲間を置いて逃げない」。2・2 → null。**文化を変えても** `genApplicants` の結果（種族・能力）が変わらない。
- 旧セーブ（`record` / `departed` / `relics` 無し）を `migrateState` で読んでも落ちず、既定値が入る。
- 既存の `tools/test-*.js` 全通過（撤退の `test-retreat-run.js` を含む。決着処理にカウンタを足しても撤退・続行の結果が変わらないこと）。

## 8. 落とし穴（既に踏んだもの）

- **部門は出撃リストから導出**。`m.department` を直接書いても効かない。`departmentRoster("combat")` は今出撃している者だけ。候補全員は `st.roster`。
- **決着処理は `settleContinue` / `settleRetreat` の二つ**。個人カウンタや離脱の記録はこの二つに入れる。`deploy()` の途中や `processCasualties` の外に書くと、引数なし `deploy()`（sim・テスト）と UI 経由（`offerRetreat`）で結果がずれる。
- **`U.rand` の消費順を変えると sim の数字が変わる**。今回は応募者の水準を変える仕様なので数字は動いてよいが、**動いた理由が `k` なのか乱数のずれなのか**を分けて報告する（`k` を元の 0.12 に戻して sim を1回取れば分かる）。
- **`genApplicants` の `legacyReturn` は応募者の1枠を差し替える**。縁の者を同じ枠に入れると片方が消える。別の枠にする。
- **`UI.set()` は見出し文字列から scene を推定**。画面の見出しを変えるなら第2引数で scene を明示する。
- **`rollApplicant(forcedTplId)`** は種族を強制できる。縁の者の種族固定はこれを使う。
- **旧セーブ**：`migrateState` に既定値を足す。`record` が無い名簿員に `record.battles++` すると落ちる。

## 9. 未決（実装前にオーナーへ。答えが無ければ既定で）

- **U1** 「目立った者」の閾値（`battles >= 6`）。既定：6。sim の平均戦闘数（7〜13）から、ランの半ばまで生きた者が残す程度。
- **U2** 引退の条件（担がれ2回連続）。既定：そのまま。負傷の長さが変わったら見直す。
