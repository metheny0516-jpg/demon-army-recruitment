# チケット F（CodeX・設計のみ）：全体マップと城下町の見た目

目的：内政を「読む」から「眺めて楽しい」へ。魔王城・城下町・王国の段階（第一幕8、第二幕6）を**一枚の地図**として見せ、
取った領地が色づき、施設を建てると絵が変わる。**今回は設計だけ**（構成・画面遷移・絵の枚数・作る順・生成プロンプト案）。
絵の制作は、オーナーが設計を見て決めてから。

## 前提（読むだけ）
- `docs/DESIGN_ECONOMY_2026-09-12.md`（城下町の施設6・銀行・税収）
- `docs/SPEC_CASTLE_MENU_2026-09-11.md`（今の城メニュー：軍団／記録／参謀の札）
- `docs/DESIGN_ACT2_2026-09-11.md`（三幕構成。第二幕の段階9〜14）
- `src/data/enemies.js` の `region`（村はずれ・街道・関所・大神殿・城塞都市・大平原・王都城門・王都、第二幕の隣国）
- 既存の画風：`assets/battle/backdrops/`、`assets/battle/units/*/idle.webp`（太いインク、くすんだマット、90年代ベスティアリ）
- 遊ぶ端末：**スマホ縦（390px）が主**、PC も。中高生にも読める字の大きさ。

## 出してほしいもの（`docs/WORLD_MAP_DESIGN_2026-09-12.md` 1本）

1. **地図の構成**：魔王城（左下）→ 城下町（城の周り）→ 村はずれ〜王都（右上へ道が伸びる）→ 第二幕の隣国（さらに奥、霧）。
   スマホでは**縦スクロール1本**で全部見える配置に（横スクロール禁止）。段階ごとの「地点」は8＋6。
2. **状態の見せ方**：未到達（灰）／前哨戦済（旗が半分）／領地（魔王軍の色に染まる）／荒らされた（煙）／防衛戦の敵が来る道（点線）。
   城下町の施設6つは Lv0（空き地）→ Lv1〜3 で絵が変わる（差分は「屋根が増える」「看板が付く」程度に留める）。
3. **画面遷移**：城メニューの「城下町」札 ⇄ 地図。地点をタップで「作戦カード」（既存の作戦会議）へ、施設をタップで建てる／銀行。
   既存の面接→作戦→編成→戦闘→結果の流れは**変えない**。地図は「眺めて選ぶ入口」。
4. **絵の枚数と仕様**：背景1枚（縦長、2段階の解像度）、地点アイコン14、施設 6×4 段階、旗・煙・点線などの小物。すべて透過 WebP。
   1枚ごとに生成プロンプト案（既存の画風に合わせる）。**合計の目安を出す**（多すぎるなら削る案も）。
5. **立体風か 2D か**：両方を1枚ずつ小さな試作（image_gen）で比較し、**スマホでの読みやすさ**で推す方を決める。理由を書く。
6. **作る順**：(a) 背景＋地点＋領地の色（税収が見える）→ (b) 城下町の施設 Lv 差分 → (c) 小物と動き。各段階で遊べる状態を保つ。
7. **実装の見取り図**：地図は `src/ui/map.js`（新）に閉じる。データは `src/data/map.js`（地点座標・施設の座標）。run.js は触らない前提で、
   必要な状態（領地・前哨・荒らされた・施設 Lv・借金）を**読むだけ**で描けることを確認する。

## 規則
- 設計文書と試作画像2枚だけ。コードは書かない。ブランチ `codex/world-map-design`。
