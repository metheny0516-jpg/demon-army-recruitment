# CHAIN V2 切替前統合レビュー（2026-09-07）

基準コミット: `9de9190`

## 結論

正規化API、保存、戦闘中UI、戦果、魔界史、KPIの**準備層は接続済み**。
ただし `Chain.RECORDED_VERSION = 2` へ変更するだけでは、版ラベルと記録値が食い違うため切替不可。
現状の `RECORDED_VERSION = 1` は正しい。

| KPIレポート | 準備済み | `Chain.versionOf()`で版別集計。混在統合値を出さない |

## 切替前の必須作業

### 1. 全15戦略×200の測定（Opus）

`tools/sim.js` の15戦略すべてで、V1記録とV2記録を同じseed・同じ戦闘結果から比較する。
最低限、最大CHAIN分布、教訓 `<=2` の条件一致・実提示、ビルド名 `>=6` の条件一致・実命名、
KPIの `chainMax / chainAbilityMax / chainSample` を版別に出す。倍率・ハプニング条件は変更しない。

測定ミスを避けるため、戦闘結果・勝敗・raw因果グラフがA/B一致しなければ停止する。

### 2. 表示モデル一本化と表示契約テスト（Sol）

現在、V2 stepのラベル生成が `UI.chainViewStepLabel()` と `BattleScene.chainStepLabel()` に複製されている。
現時点の文言は一致するが、一方だけ直すと戦闘中と戦果が静かに食い違う。

UI層の共通フォーマッタへ一本化し、期待経路9件と分岐2経路について、戦闘中・スキップ・戦果が
同じstep数、能力、行為者、宣言者、対象、召喚役を表示することを固定する。raw `text` は解析しない。

### 3. ラン記録とKPIの版別読出し（Opus）

現状は準備段階なので、次の2か所が常にV1を読む。

- `run.js`: `st.maxChain` を `result.chainSummary.maxChain` から更新
- `kpi.js`: `battleFinished()` が `result.chainSummary` とV1 `deepest.steps` を使用

切替実装では、**保存済みラン版**を正本にしてV1/V2の読出しを選ぶ。V2ランは正規化要約、V1途中ランは
従来要約を使用する。同じ戦闘内で複数回正規化して異なる値を作らず、`lastBattle.chainView` と同じ結果を使う。

### 4. 記録閾値の判断（測定後）

`st.maxChain` をV2へ切り替えると、教訓 `<=2` とビルド名 `>=6` も意味が変わる。
旧閾値のまま本番切替しない。15×200の結果を見て閾値を決め、重要な設計判断としてAstraへ戻す。

倍率、ハプニング条件、演出尺、稲妻強度、モルモの5段台詞はさらに後の別タスク。

### 5. 切替コミット

上記完了後にだけ `Chain.RECORDED_VERSION = 2` とする。

- 新規ランだけV2。
- 既存V1ランはロード・再起・再起動後もV1で完走。
- `maxChain`、戦果、魔界史、KPIはラン版と同じ値。
- V1表示は切替前と一致。
- V2表示は通常再生・倍速・スキップ・ロード後戦果で一致。
