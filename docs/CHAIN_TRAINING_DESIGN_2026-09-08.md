# 連鎖研修 — 最小実装仕様（2026-09-08）

## 目的

初見プレイヤーが、通常ランへ入る前に次の因果を自分の操作で一度だけ作る。

`《追い剥ぎ》を採用 → 《強欲》を採用 → 2体を出撃 → 金貨獲得 → 強欲が反応 → 追加攻撃`

戦闘を眺めて偶然CHAINが起きるのを待つチュートリアルにはしない。採用時点から
「この2人を組み合わせると何が起きるか」を仮説として持たせ、戦闘を答え合わせにする。

## 設計原則15節のゲート

- 新しい判断: 2枚目の履歴書を単体性能でなく、先に採った人材との接続で読む。
- 発見: 公開された2能力を自分で同時出撃させ、結果の連鎖を確認する。
- もう1回: 通常ランで別の能力同士もつながるのでは、という期待を残す。
- 作業量を増やさない: 研修は採用2回・編成1回・戦闘1回だけ。経営・施設・給与は教えない。
- 再発火への接続: 追い剥ぎの金貨が強欲を発火し、強欲の追加攻撃が次の結果を作る。

## 入口

タイトル画面に通常ランと区別した `連鎖研修（約3分）` を置く。任意選択とし、
通常ランの開始を妨げない。初回強制ポップアップや通常ランの応募固定は行わない。

研修の完了状態を保存して入口を消す必要はない。復習できることを優先する。

## 進行

### 1. 1人目を採用

- 固定応募者: ゴブリン／《追い剥ぎ》持ち。
- 通常生成ではゴブリンの《強欲》が50%抽選なので、研修用生成だけ特性を明示固定する。
  通常の `genApplicants()` や応募確率は変更しない。
- モルモは「攻撃が当たると金貨を生む」を一文で示す。
- 他の応募者や見送りは出さず、採用操作そのものはプレイヤーに押させる。

### 2. 2人目を採用

- 固定応募者: ゴブリン／《強欲》持ち。
- 1人目との接続を `追い剥ぎ → 金貨獲得 → 強欲` と表示する。
- 「強いから採る」ではなく、「先に採った者の金貨へ反応するから採る」と伝える。

### 3. 編成

- 固定2名を出撃隊へ入れる。
- 既存の「連鎖の見取り図」をそのまま使う。
- 施設・部門配属・傭兵・給与方針・作戦3択は研修では扱わない。
- 出撃前にモルモが「2人とも出撃に入っている」ことだけ確認する。

### 4. 戦闘

- 既存の本物の戦闘計算を使い、CHAINを模造した動画にはしない。
- 最初の `追い剥ぎ → 金貨獲得 → 強欲 → 追加攻撃` が成立する入力を固定する。
- 最初の人材間反応だけ自動進行を停止する。
- 同じ事実から次の3行を順に示す。
  1. `《追い剥ぎ》で金貨が発生`
  2. `金貨に《強欲》が反応`
  3. `追加攻撃へつながった`
- プレイヤーが「続きを見る」を押すまで再開しない。通常ランの速度設定は変更しない。

### 5. 戦果

- 既存のspotlightから「誰の何を受け、誰が追撃したか」を1文で表示する。
- モルモは「能力を1個ずつ見るのでなく、出したものと反応するものを組み合わせる」と締める。
- `通常ゲームへ` と `もう一度` の2択だけを置く。

## 状態と保存の契約

- 研修は通常ランの `maou_save`、`maou_history`、`maou_kpi` を変更しない。
- 通常ランの世代数、図鑑、実績、教訓、殿堂入り、KPIのラン数に数えない。
- 研修専用状態はメモリ上だけでよい。ページを閉じたら破棄する。
- 通常ランの `Game.state` を一時利用する場合も、開始前の保存データを上書きしない。
- 研修終了時は必ずタイトルへ戻せる。

## 再利用するもの

- 人材能力と実戦発火: `TRAITS` / `Battle.simulate()`
- 連鎖の事前説明: `Synergy.signalChain()` / `UI.chainMapPanel()`
- 戦闘中の答え: `BattleScene.pickChainAnswer()` の構造化事実
- 戦果の答え: `Spotlight.pick()` / `UI.spotlightText()`
- モルモ表示: Opusの戦闘中セリフ画面改善が統合された後の実装
- 分離方法の参考: `battle-preview.html#loot`（固定編成・本物の戦闘計算・本編セーブ非変更）

説明文を別系統で再生成せず、既存の構造化事実を読む。

## 実装の分割

1. **T1: 研修状態と固定2名・固定戦闘を作る。** 通常の応募抽選を変えず、研修専用ヘルパーで
   1体目を《追い剥ぎ》、2体目を《追い剥ぎ》＋《強欲》へ固定する。coreまたは研修専用モジュール＋Nodeテスト。
2. **T2: タイトル入口と採用・編成の研修画面を接続する。** UI＋390/1280pxブラウザテスト。
3. **T3: 初回CHAIN停止説明と終了導線を接続する。** Opusのモルモ改善取り込み後に実施。

T1〜T3を1コミットにまとめない。未接続の本番データは追加しない。

## 合格条件

- 研修開始から3分程度で1戦を終えられる。
- 乱数にかかわらず固定2能力の人材間CHAINが1回成立する。
- プレイヤーが操作するのは採用2回、出撃確認、説明の再開、終了選択だけ。
- 390pxで横スクロールせず、主要操作が画面外へ隠れない。
- 研修前後で通常セーブ・魔界史・KPIのJSONが完全一致する。
- 通常ランの戦闘速度、演出閾値、CHAIN倍率、ハプニング条件を変更しない。
- 試遊後、プレイヤーが「何が起点で、何が反応したか」を画面を見ずに説明できる。

## 今回は扱わないもの

- 食事・死霊・OVERKILLの研修
- 3部門、給与、施設、忠誠、事件の説明
- 通常ランの応募確率補正
- 全CHAIN段を遅くする変更
- 研修報酬や恒久強化

略奪1本で伝わることを確認してから、別系統へ広げる。
