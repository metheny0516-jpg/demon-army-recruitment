# 商品化レビュー（2026-09-04・Claude）

「売れるゲームとして何が足りないか」を、現時点のコード・データ・sim・実プレイから点検した記録。
設計憲法は `GAME_DESIGN_PRINCIPLES.md`、現行仕様は `README.md`、作業履歴は `HANDOFF.md` が正本。
この文書はそれらを書き換えず、**商品として外から見たときの評価と、次に取るべき順番**だけを書く。

根拠にしたもの:

- `node tools/sim.js 100`（17戦略 × 100ラン、2026-09-04 HEAD `a42894c`）
- Playwright による通しプレイ（PC 1280px と スマホ 390px。第8戦の勇者アレン戦で敗北、敵HP残2/360）
- `src/` 全体と `docs/` の読み合わせ

## 0. 結論を先に

**「面白さの芯」はできている。売れないとしたら芯以外が原因になる。**

芯（採用→配置→発火→敗北が物語になる）は、履歴書・事業終了届・最も追い詰めた瞬間・前代の教訓・
魔界史まで一本で繋がっており、無料テスト版として人に見せられる水準にある。
一方で、**商品としての外側**——初見の10分、繰り返す理由、絵の統一、設定、保存、配布——は
ほぼ手つかずで、ここが「1回遊んで終わり」「スクショで買われない」を生む。

順番の提案は第5節。要点は次の3つ。

1. **絵の統一（敵の絵文字を無くす）と初回導線**を、コンテンツ追加より先にやる。店頭の1枚目がこれになる
2. **「クリア後」を作る**（次代の難度・解禁・シード共有）。今はクリア＝終了で、恒久成長の器が空
3. **長編化・新種族はまだ**。連鎖の深さが平均3段で止まっている間に尺を伸ばすと、同じ壊れ方が薄まるだけ

## 2. sim と実プレイから見える「面白さの芯」の未達

### 2-1. 連鎖が浅い（最重要）

| 指標（100ラン平均） | 値 |
|---|---|
| 最大CHAIN | 2.8〜4.2（ゴブリン統一+求人のみ 6.0） |
| 代表CHAINの能力数 | 2.0〜3.7 |
| 施設Lv.3到達 | ほぼ0%（三部門均衡13%・未払い搾取23%のみ） |

Balatro型の「壊れた」実感は、異なる条件を5段以上またいだときに来る。現状は
`攻撃→追い剥ぎ→強欲` や `戦死→墓守→蘇生` のように、**各系統が1つの短い輪で閉じている**。
系統をまたぐ橋（HANDOFF 5節の《接収者》《指名手配》《城代》など）が未実装のまま。

→ **新種族より先に「橋の特性」を3〜5個**。コンテンツ数ではなく接続数（憲法 第7節）。

### 2-2. 給与・忠誠がレバーになっていない

sim全戦略で給与方針は `regular` がほぼ100%（未払いを選ぶのは「未払い搾取」戦略の202回のみ）。
未払いに反応する能力が《血の気》1つしかなく、忠誠は罰しか返さない（監査文書の指摘のまま）。
憲法 第6節「給与はゲームシステム」は、まだ看板だけ。

→ 未払い・厚遇・低忠誠・高忠誠それぞれに反応する能力を最低1つずつ。

### 2-3. 食料が「判断」ではなく「常時ペナルティ」

食料不足が100ランで500〜880回、つまり**ほぼ毎戦不足**。毎回起きる罰は判断を生まず、
ノイズになる。《飢餓の悪魔》《暴食の宴》という入口はあるので、方向は2つ。

- 基準を「足りるのが普通」に寄せ、不足を**狙って起こす**状態にする
- あるいは不足を前提に、不足時に得をする能力を増やして「飢餓ビルド」を正規化する

どちらにせよ「毎戦忠誠が下がる」だけの現状は直す。

### 2-4. 施設は「使う道が見えない」問題が半分残っている

拠点接収で入口は全ビルドに開いた（sim到達100%）。しかしLv.2以降は到達ゼロ、
選択も戦略ごとに1種固定。**「同じ施設を維持する理由」「建て替えの代償」がまだ無い**。
オーナー実プレイでも施設は未使用。ここは数値強化ではなく、施設Lv.2/3で**規則が変わる**深化で解く。

### 2-5. 求人引き直しは罠

「ゴブリン統一+求人」は引き直し2309回でクリア率14%（引き直しなし32%）。
広告費0Gで無限に引き直せるが、simでは損になっている。人間が同じ罠に落ちるなら、
引き直しに小さな代償か、引き直すほど**応募の質が偏る**（狙いが当たりやすくなる）仕組みが要る。

## 3. 商品としての外側の不足（買われるために要る）

優先度は ★ の数。

### 3-1. ★★★ 絵の不統一 — 店頭の1枚目がこれ

戦場に **味方は立ち絵、敵は🪓🛡🪨の絵文字** が混在する（スクショ `06b-battle-mid`）。
憲法 第13節「よくあるAIゲームに見せない」以前に、未完成に見える。
敵剣士のGeminiキットは準備済みなので、**敵8段階×2隊列ぶんの最低限（剣士・弓・盾・僧・勇者の5種）**を
先に埋める。モンスター側の6ポーズ拡充より優先度が高い。

### 3-2. ★★★ 初見の10分に導線がない

新規ゲーム直後に履歴書3枚（各4〜5能力）が出て、モルモは一言だけ。
「CHAIN」「OVERKILL」「発火」の語は初出で説明されない。
オーナーやAIは分かるが、**買った人はここで閉じる**（KPIの `lastScreen` で測れる）。

案: 第1代の最初の2戦だけ、モルモが**1画面1概念**で案内する。
「今日はこの1人を採るだけデス」→「並び順が配置ですヨ」→「今の、光った矢印がCHAINデス」。
固定チュートリアル画面は作らず、既存のモルモ報告の台詞分岐で済ませる。

### 3-3. ★★★ クリア後が無い

クリア率45%の戦略があり、1ラン15分。**一度クリアすると次の目標が無い。**
恒久成長を数値にしない（憲法 第10節）のは正しいが、「選択肢・組み合わせ・歴史」の器が
魔界史と図鑑（受動的に埋まる）しかない。

案（すべて数値強化ではない）:

| 施策 | 内容 | 憲法との整合 |
|---|---|---|
| 次代の難度（Ascension） | クリアするたび「警戒度の初期値」「勇者一行に1人追加」「給与相場+1G」など**規則**が1つ増える。段階選択式 | 第10節: 強さではなく規則の変化 |
| 実績＝解禁 | 7実績が今は表示のみ。達成で**魔王・敵隊列・事件・種族**を解禁する | 第10節: 選択肢が増える |
| 前代の教訓の常設化 | 一度使うと消える教訓に加え、累計で選べる「家訓」を1つ | 第11節: 歴史 |
| 殿堂入りの再応募率 | 現状低確率。実績で上げる | 第11節 |

### 3-4. ★★ 共有導線 — 「事業終了届」を画像にする

事業終了届はそのままSNS投稿に使える完成度。**「画像として保存」ボタン1つ**で口コミ導線になる。
Canvas描画で `html2canvas` 相当を自前で書くか、終了届だけ最初からCanvasで組む。
シード共有（同じ応募者列で他人と競う）は 3-6 のRNG差し替え後。

### 3-5. ★★ 設定画面がない

音量・ミュート・既定の戦闘速度・演出抑制・データ書き出し／読み込み・データ消去。
grepで `mute` / `toggleSound` に相当するUIが無い。有料ゲームでは必須。
`prefers-reduced-motion` は既に見ているので、手動スイッチを足すだけでよい。

### 3-6. ★★ 保存の脆さ

LocalStorage のみ。`file://` はブラウザにより領域が分かれ、キャッシュ消去で魔界史が消える。
最低限 **JSON書き出し／読み込み**（設定画面に同居）。Steam/スマホ化時は `storage.js`（44行）の差し替えで済む設計になっているのは良い。
`migrateState` はあるが**セーブにバージョン番号が無い**。今後の契約変更で必ず要る。

### 3-7. ★★ 乱数がシード不可

`U.rand` が `Math.random` 直呼び。デイリーチャレンジ、シード共有、リプレイ、
そして**バグ再現**のすべてに効くので、`U` を `mulberry32` 等に差し替える（13行の変更）。
simもシード固定で比較できるようになる。

### 3-8. ★ 見つけたUI不具合

- PC 1280px の部門編成で、「最前列（狙われやすい）」タグが付いた札の**名前・種族・前職が縦1列に潰れる**
  （`05-formation.png`、ゾンビ「クサ次郎」）。ヘッダ行の `flex` で名前側に `min-width` が無い
- 事件「金庫のネズミ」の選択肢が「……」1つ。ネタとしては良いが、憲法 第9節「対策・悪用・受容のいずれか」を
  満たさない**判断ゼロの事件**になっている（17事件中、選択肢が1つなのは `rats` だけ）。受容以外の枝を1本足す
- スマホ幅の戦場で、出来事バナーが敵名を隠す（`m06-battle.png`）

### 3-9. ★ ボリュームと価格

| 現状 | 数 |
|---|---|
| 種族 | 10（tier3が3） |
| 特性 | 約25 |
| シナジー | 8 |
| 施設 | 3 |
| 事件 | 17 |
| 敵段階 | 8 × 2隊列 |
| 魔王 | 3 |

初見が全要素を見るまで **2〜3時間**。itch.io / BOOTH で ¥300〜500 の帯。
Steam（¥800〜1,200）には 3-3 のクリア後と、敵絵・設定・英語が要る。

## 4. 拡張性の評価

### 4-1. 伸ばしやすいところ

- **データ追記で増える**: 種族・特性・事件・敵隊列・魔王・教訓・実績は末尾追記＋テスト1本。契約が HANDOFF 2節に文書化されている
- **連鎖基盤が汎用**: `CHAIN` はタイムライン上の因果IDで表現され、描画側は意味を知らない。橋の特性は `traits.js` と `battle.js` のフック追加だけで届く
- **描画差し替え口**: `BattleScene.play(timeline)` / `Storage` / `MormoScene` が窓口。Canvas化・Capacitor化は局所置換
- **測定が先にある**: sim・KPI・ブラウザ回帰があるので、数値変更の影響が数分で分かる。個人開発でこれは強い

### 4-2. 伸ばすと痛むところ

| 箇所 | 問題 | 手当て |
|---|---|---|
| `run.js` 1,929行 | フェーズ遷移・経済・採用・施設・事件が1オブジェクト。長編化（3幕）はここを直撃する | 幕・作戦・経済を別ファイルに切る前に、**フェーズ遷移表を1か所にまとめる**だけでも衝突が減る |
| `ui.js` 1,101行 + `styles.css` 2,394行 | 画面ごとの分割が無い。UI改修はCodeXと衝突しやすい | 画面単位のファイル分割（挙動は変えない） |
| `sim.js` | フェーズを増やすたび手で追随（HANDOFF 3-1）。教訓・引き直しを模擬しない | 「sim戦略」をデータ化し、実プレイのKPIと同じ形で出す |
| 文字列 | 全台詞が `data/` と `ui.js` のJS内に直書き。英語化は全ファイル改修になる | 今すぐ多言語化はしないが、**新規の台詞はキー化**しておく |
| 乱数 | シード不可（3-7） | `U` の差し替え |
| セーブ | バージョン無し | `state.version` を足し `migrateState` で分岐 |
| `HANDOFF.md` 2,143行 | 引き継ぎではなく日誌になっている。文脈ゼロで拾えない | 0節を「現在の状態」だけに圧縮し、履歴は `docs/CHANGELOG.md` へ |

### 4-3. 将来の器（今は作らない、ただし塞がない）

- **6〜10体の出撃**: UIは1180px幅で収容可。ルール上限は憲法改訂が先（オーナー決定どおり）
- **3幕構成**: 幕間で「ビルドが変質する」仕組み（幕ごとの応募プール変化、幕末の勇者訪問）が先。戦数を増やすだけでは同じ壊れ方が薄まる
- **装備**: 未着手。特性と同じフック形式で付けられれば新概念を増やさずに済む
- **Steam**: Electron包装、実績API、クラウドセーブ、英語、実績＝解禁。3-3〜3-7 が前提

## 6. 測定してから決めること

公開前に決めない。KPI（`copy(KPI.export())` → `node tools/kpi-report.js`）で見る。

- リトライ率 60秒以内（憲法の契約）。これが30%を切るなら 3-3 が最優先
- `lastScreen` が採用画面に集中するなら 3-2 が最優先
- 最大CHAIN の実プレイ分布。simの平均3段と同じなら 5 が最優先
- 施設選択への到達と維持。到達しても維持しないなら 7
