# 噂の札・第1便30枚（CodeX／2026-09-14）

未採用の文章案。基準は `DESIGN_INCIDENTS_2026-09-14.md` 第7節・第8-1節。前半20枚は第4節の同名案を改稿、後半10枚はその20枚にない種族×施設の組。旧案の固定損・確率分岐は、因果と後始末が見える形へ変更した。

## 読み方と共通の扱い

- 書式の「10行」に対して指定項目は12個あるため、`id / tier / door` を1行、`trace / art` を1行に併記し、追加の「なぜ」まで含めて1枚10行にした。札と札は水平線で区切る。
- プレイヤー向け本文は、伏線のrumor、選択後の結果、mormoの最大3行。結果行はgainと選ばれたlossの枝だけを一文にし、未発生の枝は見せない。「なぜ」は別の理由欄、trigger等は制作資料。
- triggerは各札の関連痕跡①②③のうち**異なるkindを2種**＋現在条件1つ。同じkindの2回で代用しない。3種揃えば最新の記録を持つ2種を使い、同順なら①→②→③で決める。採用した2本は札の提示時（Bは報告時、Cは予兆開始時）に保存し、めくるまでに差し替えない。P等は痕跡が指す同じ人物のUID。主役は現在も在籍する者から固定し、複数なら条件成立が最も古い者、同時ならUID順。全軍の痕跡はsubjectなし。在籍中・出撃時の指定はturn/seqと名簿の履歴で照合し、既存ログで判別できなければ記録の追加が必要。主役がその場で実行したと証明できない全軍の防衛痕跡は「Pたちの軍団が守った」とだけ述べる。
- rumorは①②・①③・②③の3通り。成立した組の1通りだけ表示し、未成立の過去は文に混ぜない。条件一覧や「あと1本」のヒントはUIに出さない。第8-3節の乾きによる1本判定は本便の標準条件に混ぜない別案とし、採用時には単独痕跡用の文も別途必要。
- 見学者Vは札を出す時点で対象を固定し名前を表に出す。追加状態も同じ提示時点に存在する値を保持し、選択後の乱数・後付けでは変えない。札をめくった時点では追加状態と分岐表を表示せず、結果の「なぜ」で本人名・効いた痕跡・状態の実値を明かす。
- Aは「めくらない」なら無変更・無記録、3決着で消える。めくっても「やめる」なら効果なし。Bは発生済みの小さな出来事だけ記録し、「関わらない」ではgain/loss/tailを起こさない。
- Cは波乱設定でまとめて止め、2決着前からrumorを出す。発生後の対処選択では事故そのものを取り消さない。3枚とも既存CHAOSへの**新規の引き渡し案**であり、実装済みの事故IDを名乗るものではない。
- 枚数はA18・B9・C3（60%・30%・10%）。これは抽選率ではない。第7-3節の「全部無視時、B/C由来の波乱が決着の10〜20%」は実装後のsimで検証する別条件。本文だけで達成済みとはしない。
- 同時2枚・続き物1本・同じ札は1ラン1回。札から札は深さ2まで。今回の接続候補はmimic_appraisal→mimic_hostel_locker。同札はransacked＋material_carriedでも単独で開く。incidentを採用して開いた場合だけ深さ2とし、それ以上は続けない。他のtailは既存報告欄で完結する。
- 全tailの完了時にincident〔新規、phase=tail〕を1本記録し、発生時のphase=startとは区別する。同じ札のstartとtailを2種として数えない。Bの関わらないはphase=ignoredだけでtailなし。Aの辞退は無記録。
- 中のtailは2〜3決着以内に回収する。小の期間付き効果は自動解除で、別の選択札を要求しない。slime_pondは3決着後に選択が残るため、旧表の小から中に変更。大以外は人物・施設・遺物の恒久消去をしない。資源は0未満にせず、選択時に必要な支払い額を表示する。
- 数値は試案。費用を払えない能動選択は選べないが「やめる／関わらない」は残す。Cの不足分は借金化せず、その時点の資源まで。給与加算・出撃制限・能力加算は期限後に解除し、能力を戻す際は現在HPを上限内へ収める。
- 「なぜ」の各文は理由の型。{痕跡1}・{痕跡2}には保存した2本のkindの日本語名と本人名を入れ、{追加状態の実値}・{今回の結果}にはlossで実際に採った枝の状態と結果を入れる。実表示は今回起きた枝に限定して、「あり／なし」「将軍／兵卒」などの値も添える。主役が去る・施設がなくなる等で接点が失われた未発生札は取り下げ、進行済みの返却・解除は実施する。

## 痕跡の実在確認

参照：`src/core/run.js` の `this.trace(...)`、`src/core/traces.js` の `TRACE_KINDS`、`src/data/events.js` の選択肢と遅延結果。

| この便で使う既存kind | 実際に記録している意味 |
|---|---|
| hired / promoted | 採用／昇進。promotedはdata.rankも確認する |
| downed / carried | 戦闘不能／**本人が担がれて帰った**。carriedを「誰かを運んだ」と解釈しない |
| late / ate | 戦闘への遅刻／**大食漢の発動**。ateを一般の食事・腐った食事と読み替えない |
| defended / ransacked | 城の防衛成功／城を荒らされた。個人の武功や被弾とは別 |
| retreated | 軍団の撤退。主役の出撃確認が必要で、戦闘への遅刻とは別 |
| fallen | 実際の戦死。現役主役の痕跡として要求せず、同僚の記録を使う |

`events.js` の `black_market` の裏取引と警戒度の遅延結果は実在するが、選択履歴をTracesへ保存してはいない。`oweDebt` のkindは遅延処理の種類であり、痕跡kindではない。`fermented`・`revived` は定義だけで本便の根拠にせず、研究早期習得・運搬・訓練回数も自動で既存痕跡扱いにしない。

**新規と明記した記録案**：fire_hit（対象・被弾元）、material_carried（運搬者・完了回）、event_choice（イベントID・選択・担当者）、bank_borrow / bank_repay（額・立会人）、lab_early_learn（本人・技）、experiment_failed（本人・失敗内容）、trained（担当者・師匠か参加者か・稽古内容・完了）、cooked（担当者・料理内容）、exchanged（担当者・両替内容）、water_cleaned / rain_prayed（担当者・実行）、incident（札ID・主役・結果枝・深さ・phase）。
未接続の新規kindは成立扱いにしない。関連する既存2種だけで開ける札もあるが、全札が出力するincidentの記録接続は必要。特にfire_hitをdownedから、experiment_failedを煙の絵から推測しない。新規記録の出来事自体も事前に日報へ出し、未表示の過去を後付けしない。incidentは現行の17kindに含まれず、本便全札で新規。
