## 取り込みの手順（上がったと報告されたら）
1. `git fetch`。枝が本線から切られているか確認（merge-base）。古い土台なら乗り換えさせる。
2. 差分を読み、チケット外の変更、重複実装、保存・進行・数値契約の食い違いを確認する。
3. 変更とリスクに必要な最小限だけ検証する。保存・進行不能・戦闘契約は対応するNodeテスト、UIは該当browserテスト、数値・経済は該当simまたは測定器を使う。全Node、browser全件、simを一律には要求しない。
4. 明白な不具合、進行不能、セーブ破損、バランス崩壊、無限金策などは止める。単なるテスト網羅不足や細かな表現だけでは、差し戻しと再検証を往復させない。
5. 承認時は外部Opusへ、対象コミット、確認するブラウザ範囲、取り込み先、HANDOFFへ記す「済／検証結果／次に誰へ何を」を渡す。外部Opusが通常のmergeまたはfast-forwardで本線へ入れる。
