## 0. 結論

**このままでは採用しない。第2便として12枚に絞って書き直す。** 書式と規則は正確に守られているが、札の中身が「帳簿の増減」になっていて、読んでワクワクしない。

## 1. 30枚に共通する問題（点を付ける前に）

| 問題 | 何が起きているか | 例 |
|---|---|---|
| **結果が帳簿** | 30枚中 27枚の「思わぬ向き」が「金 ±1〜3／忠誠 ±2／食料 ±1」。数字が小さすぎて何も起きていないのと同じ | 骸骨の合唱→「応募者枠 -1」。夜会→「金 3 と1ラウンド遅刻」 |
| **隠れた状態が同じ** | 30枚中 **16枚**が「本人の未払いあり／なし」で分岐。周回ごとに違う結末にならない | 闇市・帳簿・手紙・帳簿クイズ・夜番… |
| **rumor が機械的** | 「採用と仲間の戦死のあと、Sが歌を練習している」。痕跡名を並べただけで、日誌の一行に読めない | 全枚 |
| **新規の痕跡に頼りすぎ** | 新規 kind が 12 種。実装前提が重い | fire_hit / material_carried / event_choice / bank_borrow / bank_repay / lab_early_learn / experiment_failed / trained / cooked / exchanged / water_cleaned / rain_prayed / incident |
| **読めない** | 1枚10行の制作資料としては正確だが、プレイヤーに見える3行（rumor・結果・モルモ）に**顔**が無い。中高生に向けた言い方ではない | 「Vのate痕跡={追加状態の実値}だったので」 |
| **C が小さい** | 事故（C）3枚の結果が「食料1／建材1」。事故は `DESIGN_CHAOS` の規模（分身が増える・骸骨が溢れる）でないと C ではない | 蛙・冷却桶・太鼓 |

良い点：規則の読み込みは正確。**痕跡の実在確認の表**（carried は「本人が担がれた」、ate は「大食漢の発動」）は制作側の資産として残す。`mimic_appraisal → mimic_hostel_locker` の2段接続は形として正しい。

## 3. 第2便の指示（12枚）

- 枚数を **12 枚**（A 9・B 3。C は無し）。
- **思わぬ向きは「数字」ではなく「出来事」**：誰かが来る／去る／変わる／建つ／壊れる／覚える／連れ帰る。金・忠誠・食料の ±3 以下は「出来事の添え物」にしか使わない。
- **隠れた状態は 12 枚で 8 種類以上**（未払いは 2 枚まで）。使える状態：種族、将軍か、忠誠 60 以上、負傷中、遺物持ち、施設の Lv、借金あり、食料 3 以下、その決着に前哨済、同種族が 2 体以上、痕跡の本数が一番多い者か。
- **rumor は日誌の一行**として書く。痕跡名を並べない。「プルが宿舎の裏の池に、毎晩通っている」。開いた痕跡の違いは rumor では出さず、**「なぜ」欄だけ**で名指しする（3通り書かない。1通りでよい）。
- **新規の痕跡は 4 種まで**：`sparked`（火の粉。実装済み）、`carried_materials`（建材を運んだ）、`cooked`（食事を作った）、`trained`（稽古に出た）。他は既存の 18 種で。
- プレイヤーに見える3行（rumor・結果・モルモ）を**先に**書き、制作資料（trigger・状態・なぜ）を後ろに置く。3行を読んで「めくりたい」と思えなければ書き直す。
- 1枚目は必ず `slime_pond` の改稿（分身を連れ帰る／宿舎の空きを塞ぐ／3決着後に正式採用か池へ返す）。
