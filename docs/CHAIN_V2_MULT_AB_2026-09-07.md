## 1. 測定の作り

### 1回の戦闘から両方は出せない

記録の読み替え（`chain-v2-measure.js`）と違い、**倍率は戦闘へ跳ね返る**。
倍率が変われば与ダメージが変わり、撃破の順番が変わり、以後の展開がまるごと変わる。
だから同じ戦闘から両方は出せない。**同じseedで別々に走らせ、
A/B以外の入力が一致していることをassertする**方式にした。

### 差し替えるのは「倍率が読む段数」だけ

`battle.js` の写しに対して、timeline の `chainDepth` は **production のまま（raw V1）**にし、
V2の段数を `v2Depth` という**別フィールドへ並記**した。こうすると

- 記録（`record.maxChain`）・ハプニング発火条件・演出閾値は**全モードで production と同一**
- 違うのは `applyDamage` が倍率を決めるときに読む値だけ

になり、勝敗差の原因を倍率だけに絞れる。

### モード

| モード | 倍率が読む段数 | 閾値 | 倍率表 |
|---|---|---|---|
| `V1` | raw `chainDepth` | `>=3` | 現行（3で×1.25、4で×1.75、以後+0.25、上限×2.50） |
| `V2same` | `v2Depth` | `>=3` | **現行の段数閾値・倍率表をそのままV2へ適用** |
| `V2low` | `v2Depth` | `>=2` | 閾値からの相対で同じ形（2で×1.25、3で×1.75、…） |

### 停止条件（1件でも崩れたら集計しない）

1. **差し替えの透明性**: `production`（差し替えなし）と `V1` モードが全ランで一致すること。
   崩れていたら、以後の差は「差し替えの副作用」かもしれない。
   → 450ラン（15戦略 × 30ラン × 2環境）で**不一致0件**。3 seed基すべて。
2. **ラン開始時の入力の一致**: 魔王・初期資源・採用枠・応募者一覧（`tplId`・名前・能力値・
   給与・特性）がモード間で同一であること。倍率が違えば戦闘の途中から必ず食い違うので、
   比べてよいのは戦闘前の入力だけ。
   → 全戦略で一致。
3. **有効ランが揃わない**: 各戦略とも有効200ランが揃わなければ集計せず停止。

### 未完ランの扱い

単純除外せず**追加seedで補充**し、件数と戦略別内訳を別途出す。
再起で破棄された戦闘は測定へ残さない（`0ebeae7` の台帳方式を維持）。

| seed基 | 未完 | 内訳 |
|---|---|---|
| 1000 | 0 / 3000 | — |
| 2000 | 1 / 3000 | 中盤で精鋭に転換 1件（3モードとも同じseed） |
| 3000 | 1 / 3000 | 精鋭3体 1件（3モードとも同じseed） |

残る2件は「roster 1体だが唯一の生存者が生活部門で combat 0」の既知ケース。
**今回の倍率測定とは分離**し、補充と件数報告で扱った。

## 3. 発生頻度と到達倍率は別々にずれる

これが今回いちばん重要な観察である。**1つの閾値で両方は揃わない。**

`V1` モードの味方ダメージ判定（3 seed基で各34万件）から、閾値ごとの適用率:

| 閾値 | 適用率 |
|---|---|
| **現行 raw `>=3`** | **4.3 / 4.4 / 4.2%** |
| V2 `>=1` | 100%（すべての味方攻撃） |
| V2 `>=2`（`V2low`） | 10.0 / 10.2 / 10.0% |
| **V2 `>=3`（`V2same`）** | **3.5 / 3.6 / 3.4%** |
| V2 `>=4` | 0.6 / 0.6 / 0.5% |

**「V1と近い発生頻度になるよう閾値を下げる」は成立しない。**
下げると外れる。**頻度がV1に最も近いのは `>=3`、つまり `V2same` そのもの**である
（3.5% ↔ 4.3%）。`>=2` へ下げると 10% で2.4倍になる。

一方、**到達倍率はV2で圧縮される**。

| | 平均最大倍率 |
|---|---|
| `V1` | ×1.45 |
| `V2same` | ×1.17 |
| `V2low` | ×1.42 |

同じ表を当てても、V2の段数は浅いので**上の段へ届かない**。`V2low` は逆に到達倍率を
V1へ戻すが、頻度を2.4倍にしてしまう。

**頻度を合わせると倍率が下がり、倍率を合わせると頻度が上がる。**
片方の閾値だけでは両立しない。

### 4.1 `V2same` は「誰が倍率を得ているか」を絞る

倍率適用率の落ち方が戦略で大きく違う。

| 戦略 | 適用率 V1 → V2same | 平均最大倍率 V1 → V2same |
|---|---|---|
| ゴブリン統一+求人 | 29.0% → **24.6%**（ほぼ維持） | ×2.34 → ×1.91 |
| ゴブリン統一+追加採用 | 10.9% → 9.9% | ×1.98 → ×1.50 |
| 三部門均衡 | 3.2% → **0.6%**（1/5） | ×1.51 → ×1.06 |
| 未払い搾取 | 3.4% → **0.7%**（1/5） | ×1.52 → ×1.06 |
| 精鋭3体 | 1.8% → 0.6% | ×1.17 → ×1.01 |

**《追い剥ぎ》《強欲》を積んだ本物の連鎖ビルドは倍率を保ち、
そうでない戦略は倍率をほぼ失う。**
三部門均衡・未払い搾取がV1で得ていた倍率は、`death` / `overkill` を段として数えていた分
——**同じ一撃を2度3度数えていた分**である。V2はそれを取り上げる。

クリア率で最も一貫して下がるのは **ゴブリン統一+求人（−7.0 / −6.0 / −3.5pt）**。
連鎖の旗艦ビルドが最も削られる。ただし適用率は24.6%を保ち、到達最大倍率は×2.50のまま。
**壊れる瞬間そのものは残っている。**

| 戦略 | 適用率 V1 → V2low |

全体の平均最大倍率はV1と揃う（×1.42 ↔ ×1.45）が、**中身が入れ替わっている**。
連鎖を組んでいない戦略が倍率を受け取り、連鎖ビルドとの差が縮む。

## 5. 提案

### 測定値からの結論

**`V2same`（現行の段数閾値・倍率表をそのままV2へ適用）を推す。**

1. **発生頻度がV1に最も近い**（3.5% ↔ 4.3%）。閾値を下げると10%で外れる（3節）
2. **クリア率への影響が小さい**（−1.0pt）。3 seed基で符号は揃うが幅は1pt台で、
   平均勝利数・敗北地点はほぼ動かない。設計の帯（5〜50%）から出ない
3. **表を触らないので変更が最小**。閾値も倍率表もそのまま。切替は「読む値を替える」だけ

### 設計原則からの結論

同じ結論になる。

- **第4節（既存要素との接続数）**: V2は「同じ実効果を一度だけ数える」。倍率が
  `death` / `overkill` の重複計上で増えていた分は、**接続が増えたのではなく同じ一撃を
  数え直していただけ**である。`V2same` はそれを取り上げ、
  **異なる能力が実際に繋がったときにだけ倍率が乗る**状態にする
- **第5節（バランスを取りすぎない）**: `V2same` は連鎖ビルドと非連鎖ビルドの差を
  **広げる**（4.1節）。ゴブリン統一+求人は24.6%・×1.91を保ち、他は×1.06へ落ちる。
  「これ、強すぎない？」の瞬間は、**それを狙って組んだ人のところにだけ残る**
- 逆に `V2low` は倍率を全戦略へ配り直す（4.2節）。魔法職寄せの適用率が15倍になる。
  **意図して連鎖を組んでいない戦略が同じ報酬を受け取る**のは、
  第4節・第5節のどちらから見ても逆方向である

### 調整が要るとしたら

`V2same` の弱点は**到達倍率の圧縮**（平均最大 ×1.45 → ×1.17）である。
数字上は問題ないが、**体感として連鎖の頂点が鈍る**恐れがある。

直すなら**閾値ではなく倍率表**を触るのが筋だと考える。
頻度は `>=3` で合っているので、そこを動かすと3節の通り壊れる。
表の刻みを大きくする（例: 3で×1.25、4で×2.0、5以上で×2.5）方が、
「頻度は据え置き、届いたときは重い」という形にできる。

**ただしこの案は測定していない。** 提案として挙げるだけで、
採用するなら同じA/Bで測り直す必要がある。

### 判断の切り分け

| 問い | 答え |
|---|---|
| 倍率をV2へ切り替えてよいか | **測定値としては可**。`V2same` でクリア率 −1.0pt、帯を出ない |
| 調整が必要ならどの案か | まず `V2same`（無調整）。体感が鈍いと感じたら**表の刻み**を検討（未測定） |
| `V2low`（閾値引き下げ）は | **推さない。** 頻度が2.4倍になり、倍率が非連鎖戦略へ配り直される |

**採用・本番切替は行っていない。判断材料の提出まで。**
