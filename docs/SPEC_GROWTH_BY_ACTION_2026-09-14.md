# 仕様：行動で偏る成長（2026-09-14）

オーナー：「ステータスアップは戦闘後でいいが、戦闘中どの行動をとったかで上がりやすさが変わる仕様にしたい。たたかうなら攻撃力や素早さ、まもるなら防御力、ダメージを食らったら HP。技はまた考える」。

## 0. 一文で
**戦闘後の小成長は今までどおり。ただし、その戦いで「殴った者は攻撃と速さ」「守った者は防御」「殴られた者は HP」が伸びる。何もしなかった数値は伸びない。**

## 1. いまの成長（確認）
- 出撃した戦闘数 × 2.5% × 基礎値が HP・攻撃・防御に**一律**に乗る。上限 12 戦ぶん（`growthPerBattle`、`growthCapBattles`）。速さは伸びない。

## 2. 規則
- エンジンは決着ごとに `contribution[].actions = { attack, guard, skill, eat, cover }`（手番で何をしたか）と `taken`（受けたダメージ）を返す（**済み・Claude 2026-09-14**）。
- run.js は `record.grow = { hp, atk, def, spd }`（数値ごとの「伸びた戦い」の数）を持ち、決着ごとに次を足す。1戦で各 +1 まで。
  | 何をしたか | 伸びる |
  |---|---|
  | `attack` ≥ 1 | atk +1、spd +1 |
  | `guard` ≥ 1 または `cover` ≥ 1 | def +1 |
  | `taken` > 0 | hp +1 |
  | `skill` ≥ 1 | （後で決める。当面は attack と同じ扱い） |
  | `eat` | 伸びない |
- 小成長は `steps` を数値ごとに `min(record.grow[key], growthCapBattles)` にする（今の「戦闘数」の代わり）。式はそのまま（基礎値 × 2.5% × steps）。**速さ**も同じ式で伸ばす（`base.spd`、上限は同じ）。
- 旧セーブ：`record.grow` が無ければ、今の戦闘数を4つ全部に写す（それまでの伸びを失わない）。
- 訓練場でも同じ（稽古で殴れば攻撃が、守れば防御が伸びる。訓練の意味が増える）。

## 3. 見せ方
- 決着の「一回り大きくなった」の札に、伸びた数値の**印だけ**（⚔ / 🛡 / ❤ / 💨）。数字は出さない。
- 名簿の詳細に「よく殴る／よく守る／よく殴られる」の一言（`record.grow` の一番大きい項目から）。

## 4. 触るファイル
- Claude：`src/core/battle.js`（`actions`、済み）、`tools/test-skills-command.js`（済み）。
- **Opus**：`src/core/run.js`（`record.grow` の加算を `tallyBattleRecords` に、`applyGrowth` を数値ごとの steps に、spd を追加、`migrateState`）、`src/ui/ui.js`（決着の印と名簿の一言）、`tools/test-growth.js`（新：殴った者は atk/spd だけ、守った者は def だけ、殴られた者は hp、旧セーブの写し）、`tools/sim.js` は触らない。
- 数字：2.5% と上限 12 は据え置き。sim で「最強優先」のクリア率が 5 ポイント以上動いたら上限を 14 に。

## 5. 落とし穴
- `applyGrowth` は差分方式（`m.grown` に積んだ量を覚えている）。数値ごとに steps が違っても差分方式はそのまま使える。
- 自動戦闘（おまかせ・sim）でも `actions` は数えている（act() を通るので attack になる。まもるは無い）。sim の軍団は攻撃と速さに偏る。狙いどおり。
- 将軍の転身（×1.4）は現在値に掛けるので、成長の順序で結果が少し変わる。今までも同じ。
