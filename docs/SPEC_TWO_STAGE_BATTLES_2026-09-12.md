# 仕様：前哨戦と本戦 ― ランの戦闘回数を 14〜20 に（2026-09-12）

チケットC（`docs/TICKETS_SKILLS_2026-09-12.md` 7節）。担当：Opus（run.js・UI）。エンジン（battle.js）は触らない。

オーナー決定：上位技を8戦目にした。今のランの戦闘数（7〜13）では上位技が「来ない」ので、**戦闘回数を必然的に増やす設計**にする。
難度の数字は詰めない（sim は煙探知：破産率と 0% 戦略だけ見る）。

## 0. 一文で

**進軍（侵攻）の各段階を「前哨戦 → 本戦」の2戦にする。** 前哨戦は敵の一部と戦い、勝てば本戦へ。本戦に勝って初めて征服度が進む。
勇者戦（段階8）は前哨なしの一発勝負。討伐・鎮圧・防衛戦は今までどおり。

## 1. なぜ2戦制か（他案との比較）

| 案 | 戦闘数 | 弱点 |
|---|---|---|
| 段階を16に増やす | 16 | 敵データが倍要る。第二幕の設計と衝突 |
| 討伐・鎮圧を義務にする | 14〜16 | 「寄り道」の意味が消える。選択が減る |
| **前哨→本戦** | 14〜20 | 敵データは今の構成の部分集合で足りる。段階の物語（村はずれ→街道…）はそのまま。「本戦の前に様子を見る」という読みの戦いが生まれる |

## 2. 規則

### 2.1 状態
- `st.outpost`：`{ stage: <征服度 index>, cleared: true }` か `null`。今の征服度で前哨戦に勝っているか。
- 征服度（`st.conquest`）は本戦の勝ちだけで +1。前哨戦は 0。
- 旧セーブ：`outpost` が無ければ `null`（前哨戦から）。

### 2.2 作戦カード（`buildMission`）
- `invade` は `st.outpost` の状態で顔が変わる：
  - **前哨戦**（`outpost` が今の征服度で cleared でない）：`missionPhase: "outpost"`。題は「前哨戦：{region}の斥候」。
    敵は本戦の隊列（formation）から**前半**（`ceil(n/2)` 体。役つきの敵を優先して残す：shield/archer/priest を1体は含める）。
    報酬は本戦の **50%**（給与補助 `payrollSupport` はそのまま）。`conquestDelta: 0`、`alertDelta` は本戦の半分（切り上げ）。
    `formationId` は本戦に引き継ぐ（前哨で見た隊列が本戦の隊列。読みの意味を持たせる）。
  - **本戦**（cleared）：`missionPhase: "main"`。今の進軍と同じ。勝てば `conquest + 1`、`outpost = null`。
- 勇者戦（`baseIndex === MAX_CONQUEST - 1`）と第二幕・第三幕の最終段階は前哨なし（`missionPhase: "main"` のみ）。
- 討伐（raid）・鎮圧（suppress）・防衛（defend）は変えない。
- `familiarity`（守りの慣れ）は前哨・本戦の両方で `recordStageFight`。慣れは前哨で1回分進むので、本戦は少し硬い（読みの代償）。

### 2.3 決着（`applyMissionOutcome` / settle）
- 前哨戦に勝った：`st.outpost = { stage: st.conquest, cleared: true }`。日誌「{region}の前哨を制した。次は本戦」。
- 前哨戦に負けた／退いた：`outpost` は変えない（もう一度前哨から）。
- 本戦に勝った：`conquest + 1`、`outpost = null`。
- 本戦に負けた／退いた：`outpost = null`（**前哨からやり直し**。オーナー決定）。日誌「本戦で退けられた。前哨から立て直す」。
- 撤退で担いで帰った者の扱いは今までどおり。

### 2.4 経済
- 1段階の収入：前哨 50% ＋ 本戦 100% ＝ 150%。日数は2倍なので、給与・食料の圧は上がる。
- 補正は**2つだけ**：段階の `reward` を 1.15 倍（`ENEMY_STAGES` は触らず `buildMission` で掛ける。定数 `TWO_STAGE_REWARD_MULT`）、前哨戦の `foodReward` を 2。
- sim で見るもの：未払い発生率が今（41%前後）から**大きく**動いたら定数を触る。勝率・クリア率は見ない。

### 2.5 表示
- HUD の「王国攻略 3 / 8」は変えない。前哨に勝っていれば「3 / 8 ▸前哨済」。
- 作戦カード：前哨戦は題の前に「前哨戦」の帯（小さく）、本戦は「本戦」。前哨戦のカードに敵の隊列名（`formationName`）を出す。本戦も同じ隊列だと分かる一行「前哨で見た隊列と同じ」。
- 記録（城メニュー）の戦闘数は前哨も数える（技の開放は `record.battles` なので、前哨も1戦）。
- モルモ：前哨戦の前「まず斥候を叩いて、隊列を見ておきましょうカ」。本戦の前「前哨で見た顔ぶれデス。備えはお済みデスか」。各1本、`mormo_lines.js`。

### 2.6 幕の進行（`docs/SPEC_ACT_PROGRESS_2026-09-11.md`）
- 第一幕 8段階のうち 1〜7 が2戦、8（勇者）が1戦 → 進軍だけで 15 戦。討伐・鎮圧・防衛が足されて 17〜22。
- 第二幕 9〜14：13 まで2戦、14 が1戦。第三幕も同じ形。
- 上位技（8戦）は第一幕の中盤、遅咲きの 12 戦は第一幕終盤〜第二幕頭。狙いどおり。

## 4. 落とし穴
- `buildMission` は作戦会議で3枚を毎回組み直す。前哨の隊列は `st.outpost.formationId` に控えないと本戦で変わる。
- 前哨戦の敵が1体になる段階（段階1は2体 → 1体）。1体でも成立するが、狙い選びが出ない。段階1だけは本戦の2体をそのまま前哨にせず、**段階1は前哨なし**（チュートリアルの2戦目から前哨が始まる）。
- `stageFights`（慣れ）の index は征服度。前哨と本戦で同じ index に2回積む。上限（cap）があるので暴れない。
- 防衛戦（王国の反撃）が前哨と本戦の間に挟まると、本戦の隊列は据え置き（`outpost` は触らない）。
- 判定勝ち（長期戦）も勝ち。
- sim の戦略（`tools/sim.js`）は `invade` を選び続けるだけなので、変更なしで2戦制を通る。戦闘数の平均が 1.7 倍前後になることを確認。

## 5. 未決（既定）
- 前哨戦を**飛ばして本戦へ**行けるか：既定は**不可**（読みの戦いを必ず挟む）。試遊でテンポが死ぬなら「強行（前哨なし、報酬据え置き、敵に慣れ+1段）」を足す。
- 前哨に勝ったあと討伐・鎮圧へ寄り道しても `outpost` は残る：既定は**残る**。
