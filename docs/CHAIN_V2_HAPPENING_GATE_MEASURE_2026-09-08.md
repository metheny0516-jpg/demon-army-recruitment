## 1. 測定の概要と設計

### 1.1 目的

production（CHAIN倍率はV2、ハプニング発火条件はraw V1段数）と、比較案（productionからハプニング発火条件だけ正規化V2段数へ変更）を、全15戦略・各200ラン・seed基3本（計18,000ラン）で比較し、ハプニング条件のV2切替が各ハプニングの判定機会・条件成立・実発火数、および勝率・ゲーム進行に与える影響を検証する。

### 1.2 固定条件

- productionはCHAIN倍率だけV2（現行の本番挙動）
- 比較案は、productionからハプニング発火条件（`unit.chainDepth >= 3`）だけV2段数へ変更
- raw `chainDepth`、記録、倍率表、演出閾値、乱数、その他の入力は変えない
- `src/` は変更しない
- `RECORDED_VERSION` も変更しない
- `tools/sim.js` の15戦略定義・ゲーム進行・母数保証方法を直接再利用し、測定器側へ複製しない

### 1.3 モード

| モード | 説明 | パッチ | useV2Gate |
|---|---|---|---|
| `PROD_VERIFY` | 本番コードそのまま（透明性検査用） | なし | `false` |
| `PROD` | production（V2倍率・rawハプニング条件） | 計測フックのみ | `false` |
| `V2GATE` | 比較案（V2倍率・V2ハプニング条件） | 計測フック＋V2条件 | `true` |

### 1.4 停止条件と品質保証（assert）

1. **差し替えの透明性**:
   `PROD_VERIFY` と `PROD` を全15戦略×各30ラン（計450ラン）で実行し、`cleared`, `battlesWon`, `conquest`, `maxChain`, `unfinished` の不一致が **0件** であることを確認（seed基 1000 / 2000 / 3000 のすべてで不一致0件を通過）。
2. **ラン開始時の入力一致**:
   全15戦略について、各seedでのラン開始時入力（魔王・初期金貨・食料・応募者一覧）が `PROD` と `V2GATE` で完全に一致することを指紋比較で assert。
3. **有効母数の保証**:
   未完ランは追加seedで補充し、全15戦略で各200ラン（有効3000ラン/基）を厳密に保証。

### ハプニング別集計の要点

1. **`chain_receipt`（追撃より小銭）**:
   - 条件に `u.chainDepth >= 3 && u.traits.includes("greedy")` を持つ。
   - raw成立 28,909件 に対し、V2成立 28,816件（差 93件）。

## 6. 推奨案と未確認事項

### 6.1 推奨案

**ハプニング発火条件のV2切替は「安全に実施可能（低リスク）」と判断します。**

1. **勝率・難易度への影響なし**:
   クリア率差は +0.02pt、平均勝利数・敗北地点は完全に一致（差 0.00）。全15戦略においてゲームバランスを一切崩しません。
2. **設計原則との整合性**:
   V1の raw段数は `death` / `overkill` を水増し計上していましたが、V2に揃えることで「実際に異なる能力や実効果が繋がった連鎖」でのみ連鎖ハプニングが判定されるようになります。
3. **実発火数の完全維持**:
   実発火数は 91件 → 91件 であり、事件の発生頻度やプレイヤー体験の認知を損ないません。

### 6.2 未確認事項と残課題

1. **`chain_stagefright`（連鎖に出遅れ）の未発火問題**:
   今回の全15戦略測定（18,000ラン）を通じて、`chain_stagefright` は **1回も条件成立せず、1回も発火しませんでした（0件）**。
   原因は `check(u)` に `!greedy && coward` を要求している一方、`duringChain: true` で追加行動できる味方が現行エンジンでは `greedy` しか存在しないためです。
   これはV2切替の問題ではなく**既存のデータ定義・発火経路の仕様上の課題**です。連鎖中に臆病な味方が巻き込まれて出遅れる事件を成立させるには、追加行動のトリガー側またはハプニング側の条件を見直す必要があります（別タスク）。
2. **演出閾値（稲妻強度・モルモのCHAIN台詞等）は未測定**:
   演出側の閾値は本測定の対象外（raw維持）です。演出頻度への影響は別タスクでの測定が必要です。
