# BGM設計メモ — 「魔王軍が演奏している」

最終更新: 2026-09-01

当時の `GAME_DESIGN_PRINCIPLES.md` 第15節にあった8つの問いを通した結果と、その実装方針を残す。
現在の新規判断には、同節の10のゲートを使用する。
効果音（`docs/SFX_RESEARCH.md`）とは別タスク。

---

## 1. 場面差と編成差を両立する

当初は「場面ごとに曲を切り替えるだけのBGMは作らない」としていたが、実プレイで
通常進行から戦闘まで同じ旋律が続き、**戦闘の開始が耳で立ち上がらず単調**という問題が出た。
最新の明示方針を優先し、戦闘中は独立した戦闘曲へ切り替える。

ただし、画面ごとに無制限に曲を増やすのではない。通常進行の行進曲と戦闘曲の2本に絞り、
編成・昇進・未払い・忠誠・警戒度を表す同期レイヤーは両曲へ共通して重ねる。
これにより「戦闘に入った躍動感」と「自分の軍団が演奏している手触り」を両立する。

## 2. 何を作るか

**BGMは「魔王軍の行進曲」であり、鳴っているパートは軍団そのものである。**

プレイヤーが編成した軍団が、そのままバンドの編成になる。

| 鳴るもの | 鳴る条件 | 意味 |
|---|---|---|
| 足音（バスドラム） | 常時 | 行軍そのもの。テンポは警戒度で上がる |
| 行進ベース | 出撃隊の頭数 | 5体なら分厚く、1体ならスカスカ |
| 号令ラッパ | 将軍がいる（魔将は控えめ） | 昇進が耳で分かる |
| 不気味なコーラス | アンデッド（骸骨兵・ゾンビ・死霊術師）の数 | 死の軍勢は音でも死の軍勢 |
| 魔法の鈴 | 術者（インプ・魔法使い・死霊術師）の数 | 魔法結社は音が煌びやかになる |
| 間の抜けた裏拍 | スライム系がいる | ギャグ。真面目な行進曲を台無しにする |

さらに **軍団の不満（`unrest`）が演奏を壊す**。

- 給料未払いの隊員がいると、その割合だけ**音が抜ける**（サボって演奏しない）
- 平均忠誠が低いと**ピッチがずれ、拍がよれる**
- 不満が最大に近づくと行進曲が行進曲として成立しなくなる

給料を払わないと BGM がだれる。これは数値のペナルティではなく、
**耳で分かる不祥事**であり、第7節「敗北を笑える事件にする」と同じ発想。

### 当時の8つの問いへの答え

1. 新しい判断を与えるか → **YES**。「今回は安い隊で行く」が音の薄さとして返ってくる
2. 既存要素との新しい組み合わせ → **YES**。編成・昇進・未払い・忠誠・警戒度の全部に接続する
3. 発見したと感じられるか → **YES**。スライムを入れると曲が間抜けになるのは説明されない
4. プレイごとの差 → **YES**。編成が違えば曲が違う
5. もう1回遊びたい理由 → **YES**。「今度は全員アンデッドで組んだらどう鳴るか」
6. 人に話したくなるか → **YES**。「給料払わなかったら楽団がサボり始めた」
7. 画面や動画で伝わるか → **YES**。むしろ動画向き。音だけで軍団の状態が分かる
8. 作業量を増やしているだけか → **NO**。曲を6本描くのではなく、接続を1本作っている

## 3. 音源の方針（仕組み先行から、CC0実曲＋同期レイヤーへ）

効果音は「合成っぽくてちゃっちい」で差し戻しになっている。BGMで同じ轍を踏むと
丸ごと作り直しになるため、**音源の質と仕組みを切り離す**。

効果音で `Sound.cue()` の名前を契約にしたのと同じやり方を取る。

```
Music.describe(state) → descriptor → Music.apply(descriptor)
（ゲーム状態の解釈）    （契約）      （Web Audio / 将来は実素材ループ）
```

- **`descriptor` が唯一の契約**。`{ scene, bpm, layers:{名前:{gain,...}}, unrest, alert }`
- `describe()` は純関数で、DOMもAudioも触らない。だから `node tools/test-music.js` で検証できる
- 現在の `apply()` は CC0 の実曲を主役にし、Web Audio の編成差を薄く重ねる
- 別の実曲やステムへ差し替えるときも、**レイヤー名と gain の意味を保てば
  `describe()` とゲーム側は一切触らずに済む**

仕組み先行で作った契約を保ったまま、暫定の純合成だけを主役から降ろした。

## 3-1. 落とし穴: 「鳴っている」と「聞こえる」は別

初回実装は headless テスト（オシレーターが `start()` されたか）と headless ブラウザテスト
（`Music.timer` が立っているか）は全部通ったが、**実機（Androidスマホ）では無音**だった。
効果音は鳴っていたので Pages の反映漏れでもキャッシュでもなく、BGMのコード側の問題だった。

原因は2つ重なっていた。

1. `hiss()`（スネア・ハイハット等のノイズ系）に、末尾でもう一段減衰させる係数
   （`* .12`）が残っており、効果音に対して実質1桁近く小さい音量になっていた。
2. 常時鳴る「足音」がほぼ55Hz付近の純音のみで、スマホの小型スピーカーは
   この帯域をほとんど再生できない。音量は理論上出ていても耳には届かない。

**「音を生成したか」だけを測るテストは、この種のバグを検出できない。**
`tools/test-music.js` には「hiss()由来の実効音量が効果音の実効音量から
大きく懸け離れていないか」を数値で測るテストを追加した
（`createBufferSource → createGain` の生成順でノイズ系のgainだけを捕捉する）。
音量やミックスのバランスを調整したら、このテストが再び通ることを確認すること。

## 3-2. 音量を上げても直らなかった話（帯域そのものを動かした）

上の3-1を直して再確認してもらったところ、**「まだ小さい」**という回答だった。
ここで `Music.MIX` をさらに上げる対症療法は避けた。理由は2つある。

1. 効果音がすでに「合成が安っぽい」で差し戻しになっているのと同じ構図
   （Web Audio合成そのものの限界）が、音量ではなくBGMにも当てはまる可能性がある。
2. 「小さい」がオーナーの主観的な音量評価なのか、依然として特定帯域が
   スマホで再生されていないのかを切り分けられていなかった。

そこで、音量ではなく**音の作り方**を変えた。

- **足音・行進ベースの基音を、実際にスマホで再生される帯域まで上げた**
  （旧: 32〜110Hz、新: root付近〜倍音でrootの1.7〜2倍）。低い音のまま音量だけ
  上げても、そもそも出せない帯域は出せないので解決しない。
- **オクターブ上の倍音を控えめに重ねた**（欠落基音の錯覚）。基音そのものが
  再生されないスピーカーでも、耳は倍音列から元のピッチ・低さを補って聞き取る。
  これはPCスピーカーやスマホ向けの音作りで実際に使われる手法。
- **単純な波形1本を鳴らすのをやめ、わずかにデチューンした2〜3声を重ねた
  （ユニゾン）**（`Music.unison()`）。号令ラッパと魔法の鈴に適用。
  「チープなチップチューン」という印象は、音量ではなく倍音の少ない単純波形を
  単音で鳴らしていること自体が原因になりうるため。

`Music.MIX` の値自体はいじっていない。音域と音の重ね方を変えた結果として
聞こえやすくなっているはずだが、**これも実機で確認できていない**。
音量まわりだけでなく音域を触ったら、`tools/test-music.js` の
「足音・行進ベースが130Hz未満に閉じ込められていないか」のテストが
壊れるか確認すること（低い音域へ巻き戻すと実際に落ちることを確認済み）。

## 3-3. CC0実曲への差し替え（2026-09-01）

実機で「まだ小さい」が解消しなかったため、純合成をさらに調整する方針を打ち切った。
OpenGameArt の **Raiders March / Bobjt** を採用した。邪悪な軍勢・行進・オーク・RPG向けで、
CC0、ループ版あり。出典とライセンスは `assets/bgm/LICENSES.md` に固定してある。

- 元音源: 約62.44秒、123 BPM、E minor、32小節ループ
- 配信用: Ogg Vorbis 約160kbps、約1.2MB
- ラウドネス計測: 約 -15.9 LUFS、true peak 約 -1.75 dBTP
- 実曲は `Sound.master` に接続し、既存の音量・ミュートへ追従
- 場面ごとの速度差は約±8%へ抑え、過度なタイムストレッチによる劣化を避ける
- 実曲の調・テンポへ合成アクセントを同期。`Music.MIX` は `.55` から `.2` へ下げ、
  実曲が音楽の芯、軍団レイヤーは編成差の手触りという役割に分けた
- アンデッドは実曲の高域が少し曇り、未払い・低忠誠では厚みとアクセントが痩せる
- 実曲が読めない場合も同期レイヤーはフォールバックとして動く

テストは「ノードが鳴ったか」だけでなく、実曲ファイルの存在、ループ、共通masterへの接続、
再生開始、実効レベル、速度上限、BGMオフ時の停止まで見る。

## 3-4. 戦闘専用曲（2026-09-01）

戦闘では OpenGameArt の **Boss Battle Theme / Cleyton Kauffman** のループ版を使う。
通常進行の Raiders March とは旋律・編成が異なり、出撃時に曲頭から切り替わる。
決着表示では通常曲へ戻し、戦闘終了を耳でも区切る。出典は `assets/bgm/LICENSES.md`。

## 4. 実装上の約束

- `core/` と `data/` は一切触らない。BGM本体は `src/ui/music.js` に閉じ、
  `src/ui/sound.js` には MediaElementSource 非対応時の音量同期フックだけを置く
- 音量・ミュートは効果音と共有する（`Sound.master` にぶら下げる）。
  BGMだけを切りたい需要があるので `♪` トグルを別に持ち、`maou_bgm` に保存する
- 最初のユーザー操作まで鳴らさない（AudioContext の制約）
- レイヤーは1小節16ステップのステップシーケンサ。先読み方式で `setInterval` の
  ゆらぎに影響されないようにする
- 画面が非表示（`visibilitychange`）のときは止める
