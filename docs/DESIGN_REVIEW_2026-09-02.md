## 0. 総評

方向は正しい。「単純ルール × 多数の能力 × 相互作用 × 自分で発見」という Balatro 型の骨格、
「もう1回」を唯一のKPIにする姿勢、`発火 → 状態変化 → 再発火` の連鎖契約、
接続数をコンテンツ数より優先する態度、履歴書を情報兼ネタにする世界観。ここは変えるべきでない。

ただし、憲法は **「何を作るか」は良く書けているが、「プレイヤーの1分間がどう流れるか」と
「KPIをどう測るか」が抜けている**。Balatro 型の面白さは思想ではなくテンポと可読性で成立するので、
この2つが欠けたままだと、正しい思想で作った「テンポの重い経営ゲーム」になる危険がある。

以下、大きい指摘から順に書く。

## 1. 最重要の指摘（構造レベル）

### 1-1. 仮説検証1周が長すぎる。ここが「もう1回」を殺す

Balatro は「ジョーカーを買う → 30秒後に発火を見る」。検証がほぼ即時。
本作の1周は「面接 → 作戦会議 → 三部門編成 → 給与方針 → 出撃 → 自動戦闘（x1で11〜41秒）
→ 戦果 → 事件 → 面接」で、その節目ごとに **明示入力を要求する全画面モルモ報告** が入る。

さらに1ランの検証回数が少ない。8拠点＋寄り道で戦闘は10〜15回、採用は1戦1名。
Balatro は1ランで約24ブラインド・70回近い採点、Slay the Spire は約40戦。
本作は仮説を試せる回数が Balatro の 1/5 程度で、「発見」に必要な反復が足りない。

**提案**

- 戦闘は x1 でも **15秒以内** を目標にし、長い戦闘は圧縮ではなく設計で短くする
  （敵HPを下げ、ラウンド数を減らし、その代わり1発の数字を跳ねさせる）。
- 1ランの戦闘数を **12〜16** へ増やし、1戦を軽くする。3日間導入プロトタイプの「日」の
  単位をそのまま伸ばせば実装は連続する。
- 採用は **1戦で最大2名**（資金制約で自然に1名になる）。
- モルモの全画面報告は **事件・決算・初発見** だけに限定し、通常遷移は1行のふきだしにする
  （第12節「事件をモルモが持ってくる見せ方を基本にする」を「事件だけは」へ弱める）。
  モルモへの愛着はループの速さを犠牲にして買うものではない。

### 1-2. 「隠された条件」は発見ではない

現行はシナジー条件を非公開にし、発動時だけ見せる（README「条件はゲーム内に一覧表示していない」）。
これは **隠しレシピの総当たり** であり、Balatro 型の発見とは別物。Balatro は全ジョーカーの
テキストを見せる。発見されるのは「書いてある効果同士が組み合わさった結果」であり、条件ではない。

**提案**

- 憲法へ **可読性契約** を追加する。
  「人材が持つ全能力は履歴書に書く。隠すのは『組み合わせた結果』だけ」。
- 能力テキストは **1行・1トリガー・1効果・30字以内** を上限とする。
  現行の「戦闘糧食1消費につき、最も食欲旺盛な味方の与ダメージ+8%（最大80%）」は
  ゲーム的に正しいが、画面で読めない。読めない能力は仮説の材料にならない。
- 監査文書の「履歴書にヒント、編成画面に発火予告」は正しい。憲法本文へ昇格させる。

### 1-3. 数字が跳ねる設計がない

第7節は「桁違いに跳ねてもよい」と言うが、現行の設計語彙は +30%、+35%、×1.2 で、
敵HPは14から60程度へ線形に増える。これでは「壊れた」と体感できない。
Balatro が共有される最大の理由は、300 が 10,000,000 になる **画面に映る数字** である。

**提案**

- **OVERKILL% をランのスコアにする**。「最大OVERKILL 1,240%」「最大CHAIN 9」を
  戦果・魔界史・殿堂・共有画像の中心に置く。勝敗と別のスコア軸ができ、クリア後の「もう1回」の
  動機（記録更新）になる。
- 敵の耐久を後半で **指数的** に増やし、連鎖倍率も乗算で積む。線形の敵に線形のバフでは
  跳ねない。跳ねないなら OVERKILL は飾りになる。
- sim の合格帯（クリア率5〜50%）に **「最大OVERKILLの中央値と上位5%の比」** を足す。
  上位が中央値の10倍を超えていなければ壊れビルドは存在していない。

### 1-4. 「もう1回遊びたいか」を測る方法が憲法にない

唯一のKPIなのに測定方法がない。sim はバランスを測るが「もう1回」は測れない。

**提案（第14節か第16節へ追加）**

- **リトライ率**: ラン終了画面から60秒以内に「新規」を押した割合。ローカル記録で足りる。
- **1セッションのラン数** と **ラン終了→離脱** の割合。
- **共有クリック数**（後述の共有画像を作った場合）。
- 人間の試遊は5人でよいが、必ず「ラン終了後に何をしたか」だけを観察する。
  感想は聞かない。手が新規を押したかを見る。

## 2. ヒットさせるために足すべき観点

### 2-1. 誰のためのゲームかが書かれていない（第0節を作る）

憲法に対象プレイヤーがいない。対象が決まらないとプラットフォーム、セッション長、UI密度、
笑いの濃さがすべて決まらない。

提案する一文: **「Balatro や Luck be a Landlord を50時間遊び、日本語の笑いが読めるPCプレイヤー」**。
この一文から、Steam 中心、1ラン20〜30分、テキスト多め、配信向き、という判断が全部導ける。

### 2-2. 敵の設計が憲法にない（「敵は問いである」）

敵の特性は現在ほぼ無い（将軍の怪力、勇者の覚醒程度）。敵は本作で **毎戦の問い** になれる。
「回復役がいる → 瞬間火力が要る」「弱兵5人 → 火球・伝播が輝く」「大盾1体 → OVERKILLが伸びる」。
ビルドが毎戦違う問いに答える構造が、Slay the Spire の敵意図表示と同じ役割を果たす。

**提案**: 第7節に「敵編成は現在ビルドへの問いとして設計する。敵にも読める特性を持たせ、
敵の特性が味方の連鎖の発火点になってよい」を追加。作戦3択は「どの問いを受けるか」の選択になる。
これは監査文書の「作戦を発火素材を選ぶカードにする」と一致する。

### 2-3. 勇者一行を「宿敵」にする

最も安く、最も語られる物語装置。勇者アレン一行を毎ランの節目（下記の決算）に登場させ、
**プレイヤーが不採用にした応募者、離反した部下、引き抜かれた部下が勇者側に加わる**。
「未払いで逃げたオークが勇者の盾になって帰ってきた」は、第9節が求める物語が
システムから自然発生する典型で、しかも既存の離反・引き抜き・不採用の処理に接続するだけで作れる。

### 2-4. ラン終了時に「共有できる1枚」を自動生成する

第9・11・20節は「人に話したくなる」を繰り返すが、話すための道具がない。
戦闘タイムラインと事件履歴から **「第N代 魔王軍 廃業届」**（または魔界新聞）を1画面で
自動生成し、画像保存できるようにする。内容は因果の要約:
「会計係グルグの横領 → オーク3体ストライキ → 決算戦で勇者に敗北。最大OVERKILL 840%、
最大CHAIN 7、殿堂入り: 料理人ぬる」。Balatro のラン結果画面、Vampire Survivors の
配信拡散と同じ機能を果たす。憲法第11節へ「魔界史は共有できる1枚を毎ラン生む」を追加。

### 2-5. 魔王 = デッキ。開始資源ではなくルールを変える

現行の3魔王は 10G→7G、建材+5 という開始資源の差でしかない。第15節ゲート4
（プレイごとの差）に照らすと弱い。Balatro のデッキ、Spire のキャラクターは **ルール** を変える。

例:
- **ケチな魔王**: 給与は常に半額だが、忠誠上限50。低忠誠ビルドの入口。
- **死霊魔王**: 応募者は全員アンデッド。食料不要。ただし採用はGでなく魂を払う。
- **美食魔王**: 食料消費2倍。食料0で即敗北。食事バフは2倍。
- **傭兵魔王**: 全員の給与が高く忠誠が低い代わりに、応募者が毎回5名。

新魔王は発見（図鑑・実績）で解禁する。これが第10節「恒久成長は選択肢で増やす」の具体形になる。

### 2-6. クリア後の目標がない

勝つと終わる。「もう1回」は敗北時だけでなく **勝利後** にも必要。
Balatro の Stake、Spire の Ascension に相当する **「勇者の位階」**（勝つごとに次代の勇者が
強くなり、ルールが一つ増える）を第10節へ入れる。魔界史の「第N代」と自然につながる。

### 2-7. 人材を「変える」手段がない

Balatro はタロットでカードを変え、Spire は強化と除去がある。本作の変化は昇進（線形）と
解雇（除去）だけ。第8節に既に **職業訓練** の語がある。使うべき。
「職業訓練: Gを払って前職を書き換え、特性候補を差し替える」は、応募運を判断で補正する
唯一の手段になり、既存の部門適性（職業欄の部分一致）へそのまま接続する。

### 2-8. 「削るゲート」がない

10のゲートは全部「足すとき」の問い。Balatro は同種ゲームより **少ない** システムで出た。
第15節へ11番目を足す: **「これを足す代わりに、何を消せるか？」** そして四半期に一度、
「使われていないもの」を sim と試遊から拾って消す。sim 実測では、14戦略中12戦略で
施設Lvが 0.00、求人引き直しは全戦略で0回。数字が使われていないと言っている。

## 4. 私ならこうする（Fable 案・全体像）

既存コードを壊さず、憲法の思想を保ったまま、テンポと数字と物語装置を足した形。

**ランの骨格**
- 1ラン ＝ 1年度 ＝ 4四半期。各四半期は「通常戦2 ＋ 決算戦1（勇者一行）」の3戦。計12戦、20〜30分。
- 決算戦の勇者一行には、その代で不採用・離反・引き抜かれた人材が混ざる。
- 年度末に勝てば「勇者の位階」が上がり、次代のルールが一つ増える。

**1周（90秒）**
1. 求人票: 応募者3〜4名。能力は全部読める。1戦で最大2名採用。求人の出し直し、職業訓練、解雇。
2. 作戦: 3択は「どの問いを受けるか」。敵の編成と読める特性を事前開示。
3. 配置: 出撃5枠 ＋ 城内枠（施設＝規則）。誰をどの発火条件の下に置くかだけを選ぶ。生産量は見せない。
4. 戦闘: 15秒。中央に CHAIN と OVERKILL のカウンターが積み上がる。これが「採点演出」。
5. 結果: 1画面。金貨・食料・魂などの生成、初発見、事件は1つだけ。モルモは1行。

**跳ねる数字**
- 敵耐久は四半期ごとに乗算で増え、味方の連鎖倍率も乗算で積む。年度末に OVERKILL 1,000% 級が出る。
- 魔界史・殿堂・共有画像の中心はクリア可否ではなく「最大OVERKILL／最大CHAIN／滅亡の因果」。

**魔王＝ルール**
- 4〜6体の魔王が開始ルールを変える。発見で解禁。

**物語の自動生成**
- ラン終了時に「廃業届／魔界新聞」を1枚生成し、保存・共有できる。文はタイムラインと事件履歴から組む。

**測る**
- sim: クリア率5〜50% に加え、OVERKILL 上位5%／中央値 ≥ 10 を合格条件へ。
- 人間: リトライ率と1セッションのラン数を記録。感想より手の動きを見る。

**モルモ**
- 事件・決算・初発見のときだけ全画面で来る。それ以外は常駐の1行。
  「毎回そばにいる」は、毎回止めることとは違う。

## 5. 憲法へ反映するなら、この順で

1. 第0節「対象プレイヤーと測定方法」を新設（2-1、1-4）
2. 第3節へ「1周90秒・戦闘15秒」の数値目標（1-1）
3. 第7節へ「可読性契約」と「敵は問いである」（1-2、2-2）
4. 第11節へ「OVERKILL／CHAINをスコアにする」「共有できる1枚」（1-3、2-4）
5. 第10節へ「勇者の位階」、第16節相当へ「魔王はルールを変える」（2-5、2-6）
6. 第12節を短縮し、全画面の条件を限定（1-1）
7. 第15節にゲート11「削れるものはあるか」（2-8）
8. 文書を「憲法1ページ」と「設計書」に分割（3・全体）

コードへの着手順は HANDOFF の「再設計統合」の順（連鎖基盤 → 可視化 → OVERKILL）を変えなくてよい。
上の提案の大半は、その基盤ができた直後に乗る。先に決めておくべきなのは
「戦闘15秒」「能力1行」「OVERKILLをスコアにする」の3つで、これは基盤の設計に影響する。
